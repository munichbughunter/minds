1//!
2//! Ein [`Session`] ist der dauerhafte, versionierte Record einer einzelnen
3//! Agent-Session: was verlangt wurde, was das Modell getan hat und was dabei
4//! entstanden ist. Dieses Modul enthält **ausschließlich** das Datenmodell und
5//! seine serde-Anbindung — kein I/O, kein Hashing, keine Kanonisierung.
6//!
7//! Bewusste Design-Entscheidungen für Schema v1:
8//! - `schema_version` wird treu gespeichert, nicht erzwungen: ein Reader kann
9//! so erkennen, mit welcher Version die Daten geschrieben wurden. Neue
10//! Sessions bekommen über [`Session::new`] automatisch [`SCHEMA_VERSION`].
11//! - Kein `deny_unknown_fields`: unbekannte Felder werden ignoriert
12//! (Vorwärts-Toleranz, Architektur-Prinzip 4 im Plan).
13//! - `Redaction` speichert **nur Zähler, niemals Werte**.
14//! - Keine Fließkommazahlen im Envelope (Token-Zähler sind `u64`) — das hält
15//! die spätere Kanonisierung frei von Float-Formatierungsfragen.
16//!
17//! # M5: Ordnung und Herkunft, ohne Bruch
18//!
19//! Mit dem Umbau auf Hook-basiertes Capture kommen vier Felder dazu:
20//! [`Session::lineage`], [`Session::edges`], [`Turn::parent`]/[`Turn::at`] und
21//! [`ToolCall::effect`]. Alle sind additiv und tragen `skip_serializing_if` —
22//! eine Session, die keines davon belegt, serialisiert **byte-identisch** wie
23//! vorher und behält ihre `SessionId`. Deshalb bleibt [`SCHEMA_VERSION`] bei 1;
24//! ein Bump wäre eine Aussage über Inkompatibilität, die hier nicht zutrifft.
25//!
26//! Das Warum steht in [`crate::lineage`]; hier steht nur, wo es hängt.
27//!
28//! # Ein Turn ist ein Knoten, keine Zeile
29//!
30//! [`Turn::parent`] ist der Preis dafür, dass Claude Codes Transkript kein
31//! flaches Log ist, sondern ein Baum: Jedes Event verweist über `parentUuid`
32//! auf sein Elternteil. Ein `/resume`, ein Rewind oder eine Sidechain erzeugt
33//! eine Verzweigung. Plättet man die zu einer Liste, wird aus einer
34//! Verzweigung ein Widerspruch — die Erzählung enthält dann zwei einander
35//! widersprechende Fortsetzungen ohne Hinweis darauf, dass es Alternativen
36//! waren. Ein `Option<u32>` je Turn kauft das ab.
37

44#[derive(Debug, Clone, PartialEq, Eq, Serialize, Deserialize)]
45pub struct Session {
46 pub schema_version: u32,
47 pub agent: Agent,
48 pub model: Model,
49 pub intent: Intent,
50 #[serde(default)]
51 pub turns: Vec<Turn>,
52 pub usage: Usage,
53 pub produced: Produced,
54 pub redaction: Redaction,
55
56 /// Woher diese Session stammt (agent-eigene Kennung, Zeitfenster, `cwd`).
57 ///
58 /// `None` heißt „unbekannt", nicht „keine". Sessions, die vor M5 erfasst
59 /// wurden oder aus einem Adapter ohne Herkunftsinformation stammen, haben
60 /// hier nichts — und serialisieren dadurch wie vorher.
61 #[serde(default, skip_serializing_if = "Option::is_none")]
62 pub lineage: Option<Lineage>,
63
64 /// Beziehungen zu anderen Sessions und Commits, jede mit ihrer Herkunft.
65 ///
66 /// Leer ist der Normalfall beim Capture: Der Adapter sieht immer nur *eine*
67 /// Session und kann deshalb höchstens die Kanten eintragen, die im eigenen
68 /// Transkript beobachtbar sind (Sub-Agenten). Alles Übergreifende wird
69 /// später aus dem Store-Index abgeleitet.
70 #[serde(default, skip_serializing_if = "Vec::is_empty")]
71 pub edges: Vec<Edge>,
72}

74impl Session {
75 /// Erzeugt eine neue Session mit aktueller [`SCHEMA_VERSION`] und leeren
76 /// Sammelfeldern.
77 ///
78 /// `redaction.applied` startet bewusst als `false` (fail-closed): Erst
79 /// nachdem die Redaction-Pipeline gelaufen ist, darf das Flag gesetzt und
80 /// die Session gespeichert werden. Der Store weist ungeredigierte Sessions
81 /// ab.
82 pub fn new(agent: Agent, model: Model, intent: Intent) -> Self {
83 Self {
84 schema_version: SCHEMA_VERSION,
85 agent,
86 model,
87 intent,
88 turns: Vec::new(),
89 usage: Usage::default(),
90 produced: Produced::default(),
91 redaction: Redaction::default(),
92 lineage: None,
93 edges: Vec::new(),
94 }

123/// Ein einzelner Zug im Gesprächsverlauf.
124#[derive(Debug, Clone, PartialEq, Eq, Serialize, Deserialize)]
125pub struct Turn {
126 pub role: Role,
127 pub text: String,
128 #[serde(default)]
129 pub tool_calls: Vec<ToolCall>,
130
131 /// Index des Vorgänger-Turns in [`Session::turns`]; `None` = Wurzel.
132 ///
133 /// Bei einem linearen Verlauf ist das schlicht `i - 1` und damit redundant
134 /// — deshalb darf ein Adapter es weglassen, und die kanonische Form bleibt
135 /// klein. Belegt wird es dort, wo es *nicht* redundant ist: nach einem
136 /// Rewind, nach `/resume`, an einer Sidechain.
137 ///
138 /// Der Index zeigt immer nach **hinten** (`parent < eigener Index`). Ein
139 /// Vorwärtsverweis wäre ein Zyklus im Envelope; das zu prüfen ist Sache des
140 /// Validators, nicht des Typs.
141 #[serde(default, skip_serializing_if = "Option::is_none")]
142 pub parent: Option<u32>,
143
144 /// Zeitpunkt, RFC 3339 in UTC — aus dem Transkript bzw. Hook-Event,
145 /// niemals `now()` im Adapter. Zur Sortierung siehe [`crate::lineage`]:
146 /// **nicht** per String-Vergleich.
147 #[serde(default, skip_serializing_if = "Option::is_none")]
148 pub at: Option<String>,
149}
150
151/// Rolle eines Zugs. Adapter normalisieren agent-spezifische Rollennamen auf
152/// diese kanonische Menge.
153///
154/// Bewusst geschlossen für v1: eine neue Rolle wäre eine Schema-Änderung mit
155/// Versions-Bump. Falls sich das als zu eng erweist, ist der Wechsel auf einen
156/// `#[serde(other)] Unknown`-Fallback ein Einzeiler.
157#[derive(Debug, Clone, PartialEq, Eq, Serialize, Deserialize)]
158#[serde(rename_all = "snake_case")]
159pub enum Role {
160 System,
161 User,
162 Assistant,
163 Tool,
164}

166/// Ein Tool-Aufruf innerhalb eines Zugs.
167///
168/// Die Argumente werden als roher, bereits serialisierter String übernommen —
169/// so hängt der spätere Hash nicht von der JSON-Formatierung des jeweiligen
170/// Agents ab.
171#[derive(Debug, Clone, PartialEq, Eq, Serialize, Deserialize)]
172pub struct ToolCall {
173 pub name: String,
174 #[serde(default)]
175 pub arguments: String,
176
177 /// Was der Aufruf in der Welt getan hat, **normalisiert**.
178 ///
179 /// Der Pfad steckt zwar auch in `arguments` — aber dort in der Sprache des
180 /// jeweiligen Agents. Ihn später im Reader wieder herauszuparsen hieße,
181 /// Agent-Spezifika außerhalb des Adapters wiederzubeleben; genau das soll
182 /// der Adapter verhindern. Und die Secretfile-Mauer braucht ihn ohnehin,
183 /// bevor irgendetwas gespeichert wird.
184 #[serde(default, skip_serializing_if = "Option::is_none")]
185 pub effect: Option<Effect>,
186}

Absicht

Ich möchte M5 so umbauen, dass wir es genauso machen wie entire! Mit dem Hook-Ansatz. Wir bleiben erst einmal bei der Rust implementierung. Diese ist effizienter. Das ist der entscheidende Unterschied. Minds soll auch Hooks installieren im Agenten selbst: Claude Code über `.claude/settings.json`, Codex über `.codex/hooks.json`, Cursor über `.cursor/hooks.json`, Gemini über `.gemini/settings.json`, OpenCode über ein TypeScript-Plugin. Bei Codex wird zusätzlich `codex_hooks = true` in die `config.toml` geschrieben. Dazu Git-Hooks: Checkpoints entstehen, wenn du oder der Agent committen; die Session-Metadaten möchte ich entweder auf einem child-repo haben oder falls wir diese kombination nicht haben direkt im repo. Das Verhalten soll an der Stelle absolut gleich sein.
