1//! Der Checkpoint: aus Journal und Transkript werden [`Session`]s.
2//!
3//! Hier laufen die beiden Hälften zusammen, die der ganze Entwurf getrennt
4//! hält. Das **Journal** ist die Wahrheit über *Ordnung* und *Tool-Calls* — ein
5//! Beobachter mit einer Uhr hat jedes Event gesehen. Das **Transkript** ist die
6//! Wahrheit über *Inhalt* — Antworttext, Token-Zähler, Modell-ID, die im
7//! Hook-Payload nicht stehen. Der Adapter baut die Struktur aus dem Journal und
8//! füllt den Inhalt aus dem Transkript.
9//!
10//! # Deterministisch, mit Absicht
11//!
12//! Keine Uhr, kein Zufall: Alle Zeitangaben stammen aus den Events, die
13//! Token-Zähler aus dem Transkript. Derselbe Journal-Inhalt und dasselbe
14//! Transkript ergeben Byte für Byte dieselbe [`Session`] und damit dieselbe
15//! `SessionId`. Ohne diese Zusage wären die Fixture-Tests aus M5.9 nicht
16//! schreibbar und die Content-Adressierung eine Behauptung.
17//!
18//! # Was der Journal-Adapter aus den Events macht
19//!
20//! - Ein **Prompt** öffnet einen User-Zug.
21//! - Ein oder mehrere **PreToolUse** sammeln sich in *einem* Assistant-Zug; sein
22//! `at` ist der Zeitpunkt des ersten Tool-Calls.
23//! - Ein **Stop** schließt den Assistant-Zug. Hatte der Zug keine Tools (das
24//! Modell hat nur geredet), entsteht trotzdem ein leerer Assistant-Zug — sonst
25//! ginge eine reine Text-Antwort verloren, die nur das Transkript kennt.
26//!
27//! `Turn::parent` bleibt `None`: Das Journal zeigt einen linearen Verlauf, und
28//! bei einem linearen Verlauf ist der Elternindex schlicht `i-1` und damit
29//! redundant (siehe [`Turn`]). Verzweigungen aus `/resume` oder Rewind sieht der
30//! Hook nicht; sie kämen additiv aus dem Transkript.
31//!
32//! # Was hier noch *nicht* passiert
33//!
34//! Kanten (Sub-Agent, Übergabe, Commit) und der Inhalts-Hash am [`Effect`] sind
35//! M5.7. Redaction ist der Schritt *danach*: Dieser Adapter liefert die rohe,
36//! un-redigierte [`Session`]; erst `minds capture` schickt sie durch die
37//! Pipeline und in den Store. Der Store nimmt nur redigierte Sessions an — das
38//! ist ein Typ, kein Vorsatz.

53/// Der Kontext eines Checkpoints — was über die Events hinaus bekannt ist.
54///
55/// Beides ist optional, weil ein Checkpoint auch ohne beides sinnvoll ist: Ohne
56/// `root` bleiben die Artefakt-Hashes leer, ohne `commit` fehlt die
57/// Produced-Kante. Der Adapter erzwingt nichts, was die Aufrufstelle nicht hat.
58#[derive(Debug, Default, Clone, Copy)]
59pub struct Checkpoint<'a> {
60 /// Wurzel für die Auflösung relativer Effekt-Pfade beim Artefakt-Hash.
61 /// Üblicherweise die Repo-Wurzel.
62 pub root: Option<&'a Path>,
63
64 /// Der Commit, den dieser Checkpoint begleitet (post-commit-Hook).
65 pub commit: Option<&'a str>,
66}

68/// Baut aus allen Sessions eines Journals ihre [`Session`]-Records.
69///
70/// Reihenfolge ist die von [`Journal::sessions`] (Agent, dann `local_id`) — so
71/// ist auch der Rückgabewert deterministisch.
72pub fn build(journal: &Journal) -> crate::Result<Vec<Session>> {
73 let mut out = Vec::new();
74 for key in journal.sessions()? {
75 let events = journal.read(&key)?.events;
76 if events.is_empty() {
77 continue;
78 }
79 // Default-Kontext: keine Repo-Wurzel, kein Commit. Damit unterbleiben
80 // Artefakt-Hashes (kein I/O) und die Commit-Kante — aber die
81 // event-abgeleiteten Sub-Agent-Kanten kommen mit, weil sie nichts
82 // Externes brauchen. `minds capture` (M6) ruft `checkpoint` mit vollem
83 // Kontext, wenn Wurzel und Commit feststehen.
84 out.push(checkpoint(&key, &events, &Checkpoint::default()));
85 }
86 Ok(out)
87}

127/// Baut die [`Session`] und reichert sie mit dem an, was nur der Checkpoint
128/// weiß: Artefakt-Hashes an den Schreib-Effekten und die Kanten (Sub-Agent,
129/// Commit).
130///
131/// Der teure Teil — Dateien lesen und hashen — passiert nur hier, nicht in
132/// [`build_one`]: Wer nur die Struktur will (der Reader, ein Test), zahlt den
133/// I/O nicht.
134pub fn checkpoint(key: &SessionKey, events: &[JournalEvent], ctx: &Checkpoint) -> Session {
135 let mut session = build_one(key, events);
136
137 hash_artifacts(&mut session, ctx.root);
138
139 session.edges.extend(edges::subagent(key.agent(), events));
140 if let Some(commit) = ctx.commit {
141 session.edges.push(edges::commit(commit));
142 }
143
144 session
145}

147/// Füllt den Inhalts-Hash an jedem Schreib-Effekt, dessen Datei sich lesen
148/// lässt.
149///
150/// Zwei Regeln aus [`Effect`](minds_core::Effect), beide fail-closed:
151/// - Nur **Schreib**-Effekte: Der Hash ist der Fingerabdruck des *erzeugten*
152/// Artefakts. Für ihn wird die Datei gelesen, wie sie nach dem Schreiben auf
153/// der Platte liegt.
154/// - **Nie** für eine Zugangsdaten-Datei: Bei einer kurzen, ratbaren Datei wäre
155/// ein Hash ein Orakel. Die Secretfile-Mauer gilt auch für Fingerabdrücke.
156fn hash_artifacts(session: &mut Session, root: Option<&Path>) {
157 for call in session.turns.iter_mut().flat_map(|t| &mut t.tool_calls) {
158 let Some(effect) = call.effect.as_mut() else {
159 continue;
160 };
161 if effect.content.is_some() || effect.kind != EffectKind::Write {
162 continue;
163 }
164 let Some(path) = effect.path.as_deref() else {
165 continue;
166 };
167 if minds_redact::is_secret_file(path) {
168 continue;
169 }
170 if let Some(bytes) = read_artifact(root, path) {
171 let digest = blake3::hash(&bytes);
172 effect.content = Some(ContentHash::from_bytes(*digest.as_bytes()));
173 }
174 }
175}

177/// Liest die Artefakt-Datei. Absolute Pfade wie sie sind, relative gegen `root`
178/// (fehlt `root`, gegen das Arbeitsverzeichnis). Fehlt die Datei, ist das kein
179/// Fehler — der Hash bleibt dann `None`.
180fn read_artifact(root: Option<&Path>, path: &str) -> Option<Vec<u8>> {
181 let candidate = PathBuf::from(path);
182 let full = if candidate.is_absolute() {
183 candidate
184 } else {
185 match root {
186 Some(root) => root.join(candidate),
187 None => candidate,
188 }
189 };
190 fs::read(full).ok()
191}

197/// Liest das Transkript, auf das die Events zeigen — best effort.
198///
199/// Genommen wird der `transcript_path` des letzten Events, das einen trägt: Am
200/// Ende der Session ist das Transkript am vollständigsten. Fehlt die Datei oder
201/// lässt sie sich nicht lesen, ist das kein Fehler, sondern ein leeres
202/// Transkript — das Journal allein trägt die Session.
203fn read_transcript(events: &[JournalEvent]) -> Transcript {
204 let Some(path) = events
205 .iter()
206 .rev()
207 .find_map(|e| e.transcript_path.as_deref())
208 else {
209 return Transcript::default();
210 };
211
212 match fs::read(Path::new(path)) {
213 Ok(bytes) => transcript::parse(&bytes),
214 Err(_) => Transcript::default(),
215 }
216}

226/// Baut die Züge aus den Events und färbt die Assistant-Züge der Reihe nach mit
227/// den Texten aus dem Transkript ein.
228fn build_turns(agent: &str, events: &[JournalEvent], transcript: &Transcript) -> Vec<Turn> {
229 let mut turns: Vec<Turn> = Vec::new();
230 let mut open: Option<Turn> = None;
231
232 for event in events {
233 let facts = normalize::facts(agent, event);
234 match event.kind {
235 EventKind::Prompt => {
236 flush(&mut open, &mut turns);
237 turns.push(Turn {
238 role: Role::User,
239 text: facts.prompt.unwrap_or_default(),
240 tool_calls: Vec::new(),
241 parent: None,
242 at: Some(event.at.clone()),
243 });
244 }
245 EventKind::ToolPre => {
246 let turn = open.get_or_insert_with(|| assistant_turn(&event.at));
247 if let Some(tool) = facts.tool {
248 turn.tool_calls.push(ToolCall {
249 name: tool.name,
250 arguments: tool.arguments,
251 effect: tool.effect,
252 });
253 }
254 }
255 EventKind::TurnEnd => {
256 if open.is_some() {
257 flush(&mut open, &mut turns);
258 } else {
259 // Reine Text-Antwort ohne Tools: trotzdem ein Zug, sonst
260 // verschwindet, was nur das Transkript kennt.
261 turns.push(assistant_turn(&event.at));
262 }
263 }
264 _ => {}
265 }
266 }
267 flush(&mut open, &mut turns);
268
269 paint_assistant_text(&mut turns, &transcript.assistant_texts);
270 turns
271}

289/// Weist die Transkript-Texte den Assistant-Zügen der Reihe nach zu. Gibt es
290/// mehr Züge als Texte (oder umgekehrt), bleibt der Rest, wie er war — best
291/// effort, nie ein Absturz.
292fn paint_assistant_text(turns: &mut [Turn], texts: &[String]) {
293 let mut texts = texts.iter();
294 for turn in turns.iter_mut().filter(|t| t.role == Role::Assistant) {
295 if let Some(text) = texts.next() {
296 turn.text = text.clone();
297 }
298 }
299}

301/// Die von der Session geänderten Dateien: die Pfade der Schreib-Effekte,
302/// sortiert und ohne Duplikate. Lesungen zählen nicht als „produziert".
303fn produced_files(turns: &[Turn]) -> Vec<String> {
304 let mut files: Vec<String> = turns
305 .iter()
306 .flat_map(|t| &t.tool_calls)
307 .filter_map(|c| c.effect.as_ref())
308 .filter(|e| {
309 matches!(
310 e.kind,
311 minds_core::EffectKind::Write | minds_core::EffectKind::Delete
312 )
313 })
314 .filter_map(|e| e.path.clone())
315 .collect();
316 files.sort();
317 files.dedup();
318 files
319}

Absicht

Ich möchte M5 so umbauen, dass wir es genauso machen wie entire! Mit dem Hook-Ansatz. Wir bleiben erst einmal bei der Rust implementierung. Diese ist effizienter. Das ist der entscheidende Unterschied. Minds soll auch Hooks installieren im Agenten selbst: Claude Code über `.claude/settings.json`, Codex über `.codex/hooks.json`, Cursor über `.cursor/hooks.json`, Gemini über `.gemini/settings.json`, OpenCode über ein TypeScript-Plugin. Bei Codex wird zusätzlich `codex_hooks = true` in die `config.toml` geschrieben. Dazu Git-Hooks: Checkpoints entstehen, wenn du oder der Agent committen; die Session-Metadaten möchte ich entweder auf einem child-repo haben oder falls wir diese kombination nicht haben direkt im repo. Das Verhalten soll an der Stelle absolut gleich sein. M5.0 docs: Plan.md — M5 von Transkript-Parsing auf Hooks umgestellt (ADR-0003) M5.1 feat(core): Lineage, Turn.parent/at, ToolCall.effect, Vec<Edge> (additiv) M5.2 feat(capture): JournalEvent + Journal (Datei pro Event, 0600, fsck-fähig) M5.3 feat(cli): minds hook — stdin lesen, anhängen, Exit 0, immer M5.4 feat(capture): Normalisierer Claude Code (SessionStart/Prompt/Tool*/Stop/Subagent*) M5.5 feat(capture): Secretfile-Mauer bei PreToolUse M5.6 feat(capture): Journal + Transkript → Vec<Session> (Turns, Usage, Intent) M5.7 feat(capture): Kanten — Subagent (Observed), Artefakt-Hash, Commit M5.8 feat(cli): minds enable --agent claude-code (settings.json mergen, idempotent) M5.9 test(capture): Fixtures — single, subagent, zwei Agents parallel
