1//! Content-adressierte Identität einer Session.
2//!
3//! Die [`SessionId`] ist `blake3(canonical_json(session))` — der Hash *ist* die
4//! ID (Architektur-Prinzip 1 im Plan). Daraus fallen mehrere Eigenschaften
5//! gratis ab:
6//!
7//! - **Dedup:** gleicher Inhalt ⇒ gleiche ID ⇒ genau ein Objekt im Store.
8//! - **Verifizierbarkeit:** jeder Dritte (Python, Go, ein Auditor) kann die ID
9//! aus dem JSON reproduzieren, solange er dieselbe Kanonisierung (RFC 8785,
10//! siehe [`crate::canonical`]) und blake3 verwendet. Deshalb ist die
11//! Kanonisierung ein Standard und keine Haus-Erfindung.
12//! - **Stabilität über Rebase/Squash/Cherry-Pick:** die ID hängt am Inhalt der
13//! Session, nicht am Commit-Hash. Der Trailer `Minds-Session-Id: <id>` trägt
14//! sie in die Commit-Message und überlebt damit History-Rewrites.
15//!
16//! # Textform
17//!
18//! Die kanonische Textform ist `b3-<64 Hex>` in Kleinschreibung. Das Präfix
19//! `b3-` benennt den Hash-Algorithmus explizit: Käme je ein zweiter Algorithmus
20//! hinzu, blieben bestehende IDs eindeutig lesbar. Genau diese Textform steht
21//! im Commit-Trailer und in `index.json`.
22//!
23//! Dieses Modul hat **kein I/O**: es kanonisiert (in-memory) und hasht. Serde
24//! bildet die `SessionId` auf ihre Textform ab, damit sie in JSON round-trippt
25//! und mit der Trailer-/Index-Schreibweise bit-identisch ist.

35/// Präfix der Textform. Benennt den Hash-Algorithmus (blake3) und macht spätere

39/// Länge der Hex-Kodierung eines 32-Byte-blake3-Digests.
40const HEX_LEN: usize = 64;

42/// Content-adressierte Identität einer [`Session`]: `blake3(canonical_json(..))`.
43///
44/// Intern die rohen 32 Bytes des Digests. `Ord`/`Hash` sind damit ableitbar,
45/// was die Verwendung als Map-Schlüssel im Reader-Index (`index.json`) erlaubt.
46#[derive(Clone, Copy, PartialEq, Eq, Hash, PartialOrd, Ord)]
47pub struct SessionId([u8; 32]);
48
49impl SessionId {
50 /// Berechnet die ID als blake3-Hash der **kanonischen** JSON-Bytes von
51 /// `value`. Das ist der einzige Weg, eine ID aus Inhalt zu erzeugen — er
52 /// bindet sie unauflöslich an die kanonische Repräsentation.
53 pub fn of<T: Serialize>(value: &T) -> Result<Self, CanonError> {
54 Ok(Self::from_canonical_bytes(&to_canonical_json(value)?))
55 }
56
57 /// Hasht bereits kanonisierte Bytes. Nützlich, wenn die kanonische Form
58 /// ohnehin vorliegt (Store/Reader), und macht den Vertrag explizit: die ID
59 /// ist der Hash *genau dieser* Bytes.
60 ///
61 /// Der Aufrufer verbürgt sich dafür, dass `bytes` tatsächlich kanonisch sind
62 /// — sonst entsteht eine ID, die niemand reproduzieren kann.
63 pub fn from_canonical_bytes(bytes: &[u8]) -> Self {
64 Self(*blake3::hash(bytes).as_bytes())
65 }
66
67 /// Die rohen 32 Bytes des Digests.
68 pub fn as_bytes(&self) -> &[u8; 32] {
69 &self.0
70 }
71}

101/// Fehler beim Parsen einer [`SessionId`] aus ihrer Textform.
102#[derive(Debug, PartialEq, Eq, thiserror::Error)]
103pub enum SessionIdParseError {
104 /// Der `b3-`-Präfix fehlt.
105 #[error("SessionId muss mit \"b3-\" beginnen")]
106 MissingPrefix,
107
108 /// Nach dem Präfix stehen nicht genau 64 Hex-Zeichen.
109 #[error("SessionId braucht 64 Hex-Zeichen, gefunden: {0}")]
110 WrongLength(usize),
111
112 /// Ein Zeichen im Hex-Teil ist keine gültige Hex-Ziffer.
113 #[error("ungültiges Hex-Zeichen in SessionId: {0:?}")]
114 InvalidHexDigit(char),
115}

117impl FromStr for SessionId {
118 type Err = SessionIdParseError;
119
120 fn from_str(s: &str) -> Result<Self, Self::Err> {
121 let hex = s
122 .strip_prefix(SESSION_ID_PREFIX)
123 .ok_or(SessionIdParseError::MissingPrefix)?;
124 if hex.len() != HEX_LEN {
125 return Err(SessionIdParseError::WrongLength(hex.len()));
126 }
127
128 let mut bytes = [0u8; 32];
129 let raw = hex.as_bytes();
130 for (i, byte) in bytes.iter_mut().enumerate() {
131 let hi = hex_digit(raw[2 * i])?;
132 let lo = hex_digit(raw[2 * i + 1])?;
133 *byte = (hi << 4) | lo;
134 }
135 Ok(Self(bytes))
136 }
137}

139/// Akzeptiert Groß- und Kleinschreibung beim **Lesen** — ein hand-editierter
140/// oder von einer Fremdimplementierung geschriebener Trailer soll auflösbar
141/// bleiben. **Geschrieben** wird ausschließlich Kleinschreibung (siehe
142/// [`Display`](fmt::Display)), damit die Textform kanonisch ist.
143fn hex_digit(byte: u8) -> Result<u8, SessionIdParseError> {
144 match byte {
145 b'0'..=b'9' => Ok(byte - b'0'),
146 b'a'..=b'f' => Ok(byte - b'a' + 10),
147 b'A'..=b'F' => Ok(byte - b'A' + 10),
148 other => Err(SessionIdParseError::InvalidHexDigit(other as char)),
149 }
150}

Absicht

Ich möchte M5 so umbauen, dass wir es genauso machen wie entire! Mit dem Hook-Ansatz. Wir bleiben erst einmal bei der Rust implementierung. Diese ist effizienter. Das ist der entscheidende Unterschied. Minds soll auch Hooks installieren im Agenten selbst: Claude Code über `.claude/settings.json`, Codex über `.codex/hooks.json`, Cursor über `.cursor/hooks.json`, Gemini über `.gemini/settings.json`, OpenCode über ein TypeScript-Plugin. Bei Codex wird zusätzlich `codex_hooks = true` in die `config.toml` geschrieben. Dazu Git-Hooks: Checkpoints entstehen, wenn du oder der Agent committen; die Session-Metadaten möchte ich entweder auf einem child-repo haben oder falls wir diese kombination nicht haben direkt im repo. Das Verhalten soll an der Stelle absolut gleich sein.
