1//! Die Mauer vor Zugangsdaten-Dateien — durchgesetzt auf dem heißen Pfad.
2//!
3//! [`minds_redact::secretfile`] liefert seit M2 nur das *Prädikat* („ist dieser
4//! Pfad eine Zugangsdaten-Datei?") und kündigt an, dass die Durchsetzung in
5//! `minds-capture` sitzt. Das ist dieses Modul.
6//!
7//! # Was hier geschützt wird und warum am Hook
8//!
9//! Liest ein Agent eine `.env`, trägt das **PostToolUse**-Event ihren gesamten
10//! Inhalt im `tool_response`. Genau dieser Inhalt soll nirgends aufgehoben
11//! werden — auch nicht im lokalen Journal, das zwar 0600 und außerhalb von Git
12//! liegt, aber eben doch auf der Platte. `hook.rs` hat diese offene Flanke bis
13//! hierher benannt; [`guard`] schließt sie, *bevor* das Byte geschrieben wird.
14//!
15//! Der Milestone heißt „Mauer bei PreToolUse", weil die Entscheidung
16//! **pfad-basiert** ist: Der Pfad steht schon im PreToolUse fest, lange bevor
17//! der Inhalt existiert. Ein Detektor über den Inhalt wäre die falsche Bauform
18//! (siehe [`minds_redact::secretfile`]) — bei einer Datei, deren einziger Zweck
19//! Zugangsdaten sind, ist die einzige belastbare Aussage: *alles hier drin ist
20//! verdächtig.* Deshalb wird nicht geschwärzt, sondern **weggelassen**.
21//!
22//! # Was bleibt, was geht
23//!
24//! Erhalten bleiben Tool-Name und Pfad — beides kein Geheimnis (der Pfad kann
25//! einen Benutzernamen enthalten, aber das ist PII und Sache der Pipeline auf
26//! dem kalten Pfad, nicht der Mauer). Ersetzt wird **alles Übrige**, allen voran
27//! `tool_response`. Der Reader sieht am Marker [`minds_redact::SECRET_FILE_PLACEHOLDER`],
28//! dass hier eine ganze Datei ausgelassen wurde — nicht ein einzelner Wert.
29//!
30//! # Grenzen, ehrlich benannt
31//!
32//! Lässt sich der Payload nicht deuten (abgeschnitten, fremdes Format), kann die
33//! Mauer den Pfad nicht sehen und greift nicht — das Event geht unverändert ins
34//! Journal. Das ist bewusst fail-**open** wie der ganze Hook: Die permanente
35//! Grenze liegt ohnehin auf dem kalten Pfad, wo derselbe Pfad-Test über den
36//! [`Effect`](minds_core::Effect) erneut greift und zusätzlich entscheidet, dass
37//! für eine solche Datei **kein Inhalts-Hash** gebildet wird (M5.6/M5.7). Das
38//! Journal ist die ephemere, lokale Stufe; der Store ist die, die zählt.
39

47/// Prüft ein Tool-Event und ersetzt seinen Payload, falls er eine
48/// Zugangsdaten-Datei berührt. Gibt den Regelnamen zurück, wenn die Mauer
49/// gegriffen hat — für Diagnose und Audit.
50///
51/// Nicht-Tool-Events und Tool-Events auf gewöhnliche Dateien bleiben Byte für
52/// Byte unangetastet.
53pub fn guard(event: &mut NewEvent) -> Option<&'static str> {
54 if !matches!(event.kind, EventKind::ToolPre | EventKind::ToolPost) {
55 return None;
56 }
57
58 let tool: Tool = serde_json::from_str(event.payload.get()).ok()?;
59 let name = tool.tool_name?;
60 let (path_key, path) = tool.tool_input.as_ref().and_then(ToolInput::path)?;
61 let reason = secret_file_reason(path)?;
62
63 event.payload = sanitized(&name, path_key, path, reason);
64 Some(reason)
65}
66
67/// Baut den minimalen Ersatz-Payload: Tool-Name, der Pfad unter seinem
68/// Originalschlüssel, der Auslass-Marker und der Grund.
69fn sanitized(name: &str, path_key: &str, path: &str, reason: &str) -> Box<RawValue> {
70 let value = serde_json::json!({
71 "tool_name": name,
72 "tool_input": { path_key: path },
73 "minds_omitted": SECRET_FILE_PLACEHOLDER,
74 "minds_secret_file_reason": reason,
75 });
76 // `serde_json::json!` erzeugt per Konstruktion gültiges JSON.
77 RawValue::from_string(value.to_string()).expect("json! ist gültiges JSON")
78}

80/// Nur die Felder, die die Mauer braucht: Tool-Name und der eine Pfad.
81#[derive(Debug, Deserialize)]
82struct Tool {
83 tool_name: Option<String>,
84 tool_input: Option<ToolInput>,
85}
86
87#[derive(Debug, Deserialize)]
88struct ToolInput {
89 file_path: Option<String>,
90 notebook_path: Option<String>,
91}
92
93impl ToolInput {
94 /// Der berührte Pfad samt seinem Schlüssel — `file_path` hat Vorrang,
95 /// `notebook_path` ist der Sonderfall von `NotebookEdit`.
96 fn path(&self) -> Option<(&'static str, &str)> {
97 if let Some(p) = &self.file_path {
98 Some(("file_path", p))
99 } else {
100 self.notebook_path.as_deref().map(|p| ("notebook_path", p))
101 }
102 }
103}

Absicht

Ich möchte M5 so umbauen, dass wir es genauso machen wie entire! Mit dem Hook-Ansatz. Wir bleiben erst einmal bei der Rust implementierung. Diese ist effizienter. Das ist der entscheidende Unterschied. Minds soll auch Hooks installieren im Agenten selbst: Claude Code über `.claude/settings.json`, Codex über `.codex/hooks.json`, Cursor über `.cursor/hooks.json`, Gemini über `.gemini/settings.json`, OpenCode über ein TypeScript-Plugin. Bei Codex wird zusätzlich `codex_hooks = true` in die `config.toml` geschrieben. Dazu Git-Hooks: Checkpoints entstehen, wenn du oder der Agent committen; die Session-Metadaten möchte ich entweder auf einem child-repo haben oder falls wir diese kombination nicht haben direkt im repo. Das Verhalten soll an der Stelle absolut gleich sein.
