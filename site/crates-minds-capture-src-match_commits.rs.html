1//! Die Vermutung, welcher Commit zu welcher importierten Session gehört.
2//!
3//! Eine Hook-erfasste Session weiß ihren Commit (der post-commit-Hook reicht ihn
4//! herein). Eine **importierte** Session weiß ihn nicht — das Transkript kennt
5//! keinen Git-Hash. Dieses Modul rät ihn, und zwar aus zwei Signalen, die beide
6//! vorliegen:
7//!
8//! - **Dateien.** Was die Session geschrieben hat (`produced.files`), geschnitten
9//! mit dem, was ein Commit geändert hat. Kein gemeinsamer Pfad, keine Kante.
10//! - **Zeit.** Der Commit muss im Zeitfenster der Session liegen (plus etwas
11//! Karenz davor und danach) — sonst würde eine Session an *jeden* Commit
12//! geheftet, der ihre Datei je berührt hat, quer durch die Historie.
13//!
14//! # Warum das eine Vermutung bleibt
15//!
16//! Beides zusammen ist ein starkes Indiz, aber kein Beweis: Zwei Sessions am
17//! selben Nachmittag an derselben Datei sind nicht sicher auseinanderzuhalten.
18//! Deshalb trägt die Kante im Store-Index [`Evidence::Inferred`](minds_core::Evidence::Inferred)
19//! und nicht `Observed`, und der Reader zeigt sie grau. Ehrlich vermutet schlägt
20//! falsch behauptet.
21//!
22//! # Rein, damit prüfbar
23//!
24//! Dieses Modul liest kein Git. Es bekommt die Fingerabdrücke von Commits und
25//! Sessions herein und gibt Kanten heraus — eine Funktion über einfache Daten.
26//! Woher die Commit-Daten kommen (`git log`, `git show`), entscheidet der
27//! Aufrufer.
28
29use minds_core::{Session, SessionId};
30
31use crate::clock::epoch_seconds_from_rfc3339;
32
33/// Karenz **vor** dem ersten Transkript-Zeitpunkt (Sekunden). Klein: ein Commit
34/// entsteht praktisch nie, bevor die Arbeit begann.
35pub const GRACE_BEFORE: i64 = 300;
36
37/// Karenz **nach** dem letzten Transkript-Zeitpunkt (Sekunden). Großzügiger: der
38/// Commit kommt oft kurz nach dem letzten Modell-Zug, manchmal von Hand etwas
39/// später.
40pub const GRACE_AFTER: i64 = 3_600;
41
42/// Der Fingerabdruck eines Commits fürs Matching.
43#[derive(Debug, Clone, PartialEq, Eq)]
44pub struct CommitInfo {
45 /// Voller Commit-Hash in Hex.
46 pub hex: String,
47 /// Autor-Zeit in Sekunden seit Epoch (Git liefert sie mit `%at` direkt so).
48 pub epoch: i64,
49 /// Die vom Commit geänderten Dateien, repo-relativ.
50 pub files: Vec<String>,
51}
52
53/// Der Fingerabdruck einer Session fürs Matching.
54#[derive(Debug, Clone, PartialEq, Eq)]
55pub struct SessionInfo {
56 /// Die Session-Id.
57 pub id: SessionId,
58 /// Die geschriebenen Dateien, repo-relativ (`produced.files`).
59 pub files: Vec<String>,
60 /// Beginn in Sekunden seit Epoch, falls das Transkript einen Zeitpunkt gab.
61 pub start: Option<i64>,
62 /// Ende, dito.
63 pub end: Option<i64>,
64}
65
66impl SessionInfo {
67 /// Zieht den Fingerabdruck aus einer Session: `produced.files` und das
68 /// Zeitfenster aus `lineage.started_at`/`ended_at`.
69 pub fn of(id: SessionId, session: &Session) -> Self {
70 let (start, end) = session
71 .lineage
72 .as_ref()
73 .map(|l| {
74 (
75 l.started_at.as_deref().and_then(epoch_seconds_from_rfc3339),
76 l.ended_at.as_deref().and_then(epoch_seconds_from_rfc3339),
77 )
78 })
79 .unwrap_or((None, None));
80
81 Self {
82 id,
83 files: session.produced.files.clone(),
84 start,
85 end,
86 }
87 }
88}

90/// Eine gefundene Zuordnung.
91#[derive(Debug, Clone, PartialEq, Eq)]
92pub struct Link {
93 /// Der Commit-Hash in Hex.
94 pub commit: String,
95 /// Die zugeordnete Session.
96 pub session: SessionId,
97}
98
99/// Ordnet Sessions Commits zu — jede Kante ein starkes Indiz, keine Gewissheit.
100pub fn match_sessions(sessions: &[SessionInfo], commits: &[CommitInfo]) -> Vec<Link> {
101 let mut links = Vec::new();
102 for session in sessions {
103 for commit in commits {
104 if fits(session, commit) {
105 links.push(Link {
106 commit: commit.hex.clone(),
107 session: session.id,
108 });
109 }
110 }
111 }
112 links
113}
114
115/// Passt diese Session zu diesem Commit?
116fn fits(session: &SessionInfo, commit: &CommitInfo) -> bool {
117 shares_a_file(&session.files, &commit.files) && in_window(session, commit.epoch)
118}
119
120/// Teilen sich beide mindestens eine Datei?
121fn shares_a_file(a: &[String], b: &[String]) -> bool {
122 a.iter().any(|f| b.contains(f))
123}
124
125/// Liegt `epoch` im (großzügigen) Zeitfenster der Session?
126///
127/// Ohne Zeitangaben gibt es kein Fenster — dann **kein** Match, statt eine
128/// Datei quer durch die Historie zu heften.
129fn in_window(session: &SessionInfo, epoch: i64) -> bool {
130 let (Some(start), Some(end)) = (session.start, session.end) else {
131 return false;
132 };
133 (start - GRACE_BEFORE) <= epoch && epoch <= (end + GRACE_AFTER)
134}

Absicht

Ich möchte M5 so umbauen, dass wir es genauso machen wie entire! Mit dem Hook-Ansatz. Wir bleiben erst einmal bei der Rust implementierung. Diese ist effizienter. Das ist der entscheidende Unterschied. Minds soll auch Hooks installieren im Agenten selbst: Claude Code über `.claude/settings.json`, Codex über `.codex/hooks.json`, Cursor über `.cursor/hooks.json`, Gemini über `.gemini/settings.json`, OpenCode über ein TypeScript-Plugin. Bei Codex wird zusätzlich `codex_hooks = true` in die `config.toml` geschrieben. Dazu Git-Hooks: Checkpoints entstehen, wenn du oder der Agent committen; die Session-Metadaten möchte ich entweder auf einem child-repo haben oder falls wir diese kombination nicht haben direkt im repo. Das Verhalten soll an der Stelle absolut gleich sein.
