1//! Der Commit-Index: die Verknüpfung Commit → Session, die *nicht* im Commit
2//! steht.
3//!
4//! Der verbindliche Verweis Commit → Session ist der Trailer in der
5//! Commit-Message; er überlebt Rebase und ist [`Observed`](minds_core::Evidence::Observed).
6//! Aber ein Trailer lässt sich nur an **HEAD** sicher nachrüsten (siehe
7//! `minds-cli::checkpoint`). Für alles Ältere — vor allem für **importierte**
8//! Sessions (ADR-0004) — bräuchte man ein History-Rewrite, das jeden Klon
9//! bricht. Das ist ausgeschlossen.
10//!
11//! Dieser Index ist der Ausweg: eine Zuordnung als **Daten** neben den Sessions
12//! (`index.json`), die keine History anfasst. `minds show`/`why`/`render`/`fsck`
13//! lesen Trailer **und** Index; der Reader zeigt die eine Sorte als beobachtet,
14//! die andere als vermutet. Und weil der Index in `refs/minds/context` liegt,
15//! reist er beim Push des Refs mit — der Kontext erreicht so ein geteiltes Repo.
16//!
17//! # Warum jede Kante ihre Herkunft trägt
18//!
19//! Dieselbe Leitregel wie bei den [`Edge`](minds_core)-Kanten: Ein
20//! ungekennzeichneter Pfeil wäre eine Behauptung, die wir nicht decken. Eine
21//! importierte Zuordnung ist heuristisch (die geschriebenen Dateien der Session,
22//! geschnitten mit denen eines Commits im Zeitfenster) — also
23//! [`Inferred`](minds_core::Evidence::Inferred). Ein Reader darf „vermutet" von
24//! „beobachtet" unterscheiden; ohne das Feld müsste er beides gleich behandeln
25//! und wäre im Zweifel unehrlich.

32/// Eine Zuordnung Commit → Sessions, jede Kante mit ihrer Herkunft.
33///
34/// Serialisiert als schlichtes Objekt `{ "<commit-hex>": [ … ] }`, damit ein
35/// Fremdleser (Auditor, ein Skript) es ohne Kenntnis des Wrappers versteht.
36#[derive(Debug, Clone, Default, PartialEq, Eq, Serialize, Deserialize)]
37#[serde(transparent)]
38pub struct CommitIndex {
39 commits: BTreeMap<String, Vec<IndexLink>>,
40}
41
42/// Eine einzelne Kante: welche Session, und woher wir das wissen.
43#[derive(Debug, Clone, PartialEq, Eq, Serialize, Deserialize)]
44pub struct IndexLink {
45 /// Die verknüpfte Session.
46 pub session: SessionId,
47 /// Woher die Verknüpfung stammt. Für Importe [`Evidence::Inferred`].
48 pub evidence: Evidence,
49}
50
51impl CommitIndex {
52 /// Ein leerer Index.
53 pub fn new() -> Self {
54 Self::default()
55 }
56
57 /// Trägt eine Kante ein — idempotent: dieselbe Session am selben Commit gibt
58 /// es nur einmal. Kommt sie mit stärkerer Herkunft erneut, gewinnt die
59 /// stärkere (`max` über [`Evidence`], das dafür geordnet ist).
60 pub fn link(&mut self, commit_hex: impl Into<String>, session: SessionId, evidence: Evidence) {
61 let links = self.commits.entry(commit_hex.into()).or_default();
62 if let Some(existing) = links.iter_mut().find(|l| l.session == session) {
63 existing.evidence = existing.evidence.max(evidence);
64 } else {
65 links.push(IndexLink { session, evidence });
66 }
67 }
68
69 /// Die Kanten eines Commits — leer, wenn keiner eingetragen ist.
70 pub fn links_of(&self, commit_hex: &str) -> &[IndexLink] {
71 self.commits
72 .get(commit_hex)
73 .map(Vec::as_slice)
74 .unwrap_or(&[])
75 }
76
77 /// Wie viele Commits eine Kante tragen.
78 pub fn len(&self) -> usize {
79 self.commits.len()
80 }
81
82 /// `true`, wenn keine Kante eingetragen ist.
83 pub fn is_empty(&self) -> bool {
84 self.commits.is_empty()
85 }
86
87 /// Alle Commits mit ihren Kanten.
88 pub fn iter(&self) -> impl Iterator<Item = (&String, &[IndexLink])> {
89 self.commits.iter().map(|(c, links)| (c, links.as_slice()))
90 }
91}

Absicht

Ich möchte M5 so umbauen, dass wir es genauso machen wie entire! Mit dem Hook-Ansatz. Wir bleiben erst einmal bei der Rust implementierung. Diese ist effizienter. Das ist der entscheidende Unterschied. Minds soll auch Hooks installieren im Agenten selbst: Claude Code über `.claude/settings.json`, Codex über `.codex/hooks.json`, Cursor über `.cursor/hooks.json`, Gemini über `.gemini/settings.json`, OpenCode über ein TypeScript-Plugin. Bei Codex wird zusätzlich `codex_hooks = true` in die `config.toml` geschrieben. Dazu Git-Hooks: Checkpoints entstehen, wenn du oder der Agent committen; die Session-Metadaten möchte ich entweder auf einem child-repo haben oder falls wir diese kombination nicht haben direkt im repo. Das Verhalten soll an der Stelle absolut gleich sein.
