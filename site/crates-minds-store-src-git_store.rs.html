1//! Die gemeinsame Implementierung beider Backends.
2//!
3//! [`GitStore`] ist ein Kontext-Store in **einem** Git-Repository unter **einem**
4//! Ref. Welches Repository das ist, weiß er nicht und muss er nicht wissen —
5//! genau darin besteht der Unterschied zwischen In-Repo und Child-Repo, und in
6//! nichts sonst (Plan: „identischer Baum, nur in einem separaten Repo").
7//!
8//! Deshalb ist dieser Typ privat und die beiden öffentlichen Backends
9//! ([`InRepoStore`](crate::InRepoStore), [`ChildRepoStore`](crate::ChildRepoStore))
10//! sind Hüllen darum. Der Nutzen ist keiner der Bequemlichkeit, sondern der
11//! Nachweisbarkeit: Es gibt **eine** Stelle, die Pfade baut und Refs bewegt.
12//! Zwei Implementierungen könnten auseinanderlaufen; diese eine kann es nicht,
13//! und `both_backends_write_the_same_tree` in `child_repo.rs` weist es nach.
14//!
15//! # Der Schreibweg
16//!
17//! ```text
18//! write_blob(bytes) → write_tree(bisheriger Baum + Pfad) → commit_tree_to_ref
19//! ```
20//!
21//! Genau die Reihenfolge, die Git vorgibt: erst Inhalt, dann Baum, dann Commit,
22//! dann Ref.
23//!
24//! # Dedup hat zwei Schichten, und nur die untere ist die Garantie
25//!
26//! **Unten steht Git.** Gleiche Bytes ergeben denselben Blob-Hash, gleicher Blob
27//! unter gleichem Pfad denselben Baum-Hash, und `commit_tree_to_ref` schreibt
28//! keinen Commit, wenn der Ref schon auf diesen Baum zeigt. Ein zweites `put`
29//! derselben Session bleibt damit folgenlos, **auch wenn es niemand kommen
30//! sieht** — zwei parallele Läufe, die beide „ist noch nicht da" feststellen,
31//! landen trotzdem bei einem Eintrag. [`Put::AlreadyPresent`] ist dieses
32//! `RefUpdate::Unchanged`, eine Ebene höher übersetzt.
33//!
34//! **Oben steht ein Vergleich.** [`GitStore::put_bytes`] sieht zuerst nach, ob
35//! unter dem Pfad schon genau diese Bytes liegen, und hört dann sofort auf. Das
36//! ist eine Abkürzung, keine zweite Zusage: Sie spart den Baum, und der wächst
37//! mit dem Store. Ohne sie kostet ein wiederholtes `put` bei N Sessions einen
38//! neu geschriebenen Baum mit N Einträgen — folgenlos, aber nicht gratis, und
39//! ein `post-commit`-Hook wiederholt gern.
40//!
41//! Verglichen werden **Bytes, nicht bloß die Existenz**. Der Unterschied fällt
42//! nur in einem Fall auf, aber in dem zählt er: Liegt unter dem Session-Pfad
43//! etwas Fremdes (jemand hat den Blob ersetzt), meldete eine reine
44//! Existenzprüfung „liegt schon da" und ließe den Store kaputt. Der
45//! Byte-Vergleich fällt durch, der reguläre Weg läuft, und der richtige Inhalt
46//! steht wieder da. Repariert wird dabei sichtbar — es entsteht ein Commit.
47//!
48//! # Wettläufe werden wiederholt, nicht gemeldet
49//!
50//! Ein `post-commit`-Hook und ein Aufruf von Hand reichen für zwei gleichzeitige
51//! `minds capture`. `commit_tree_to_ref` erkennt das (Compare-and-Swap) und
52//! bricht mit `RefRaced` ab, statt die fremde Session zu überschreiben. Der
53//! richtige Umgang damit ist neu aufzusetzen und es noch einmal zu versuchen —
54//! und das gehört hierher und nicht in die CLI: Es ist nichts zu entscheiden,
55//! nur zu wiederholen. Nach [`PUT_ATTEMPTS`] Versuchen gibt der Store auf; wer
56//! dann noch verliert, hat kein Wettlauf-Problem, sondern eines mit dem Ref.
57//!
58//! # Ein fehlender Ref ist ein leerer Store
59//!
60//! Vor dem ersten `minds capture` gibt es `refs/minds/context` nicht. `list`
61//! liefert dann eine leere Liste, `get` ein `None` — dieselbe Linie wie in
62//! `minds-git`: Was regulär vorkommt, ist kein Fehler.
63//!
64//! # `exists` bleibt beim Default
65//!
66//! Der Trait-Default liest den Blob und wirft ihn weg. Billiger ginge es mit
67//! einem reinen Baum-Lookup, aber `minds-git` bietet ihn heute nicht an, und
68//! eine Session ist ein paar Kilobyte. Kommt die Abkürzung, ist sie eine
69//! Ergänzung dort und ein Vierzeiler hier.

132 /// Ein Schreibversuch: Blob, Baum, Commit, Ref.
133 ///
134 /// Gibt den Git-Fehler unverpackt zurück, damit [`GitStore::put_bytes`] den
135 /// Wettlauf noch erkennen kann — durch die [`StoreError`]-Fassade hindurch
136 /// ginge das nicht mehr.
137 fn write_once(&self, path: &str, session: &SessionBytes) -> minds_git::Result<RefUpdate> {
138 self.write_blob_once(path, session.as_bytes(), &commit_message(session.id()))
139 }

141 /// Legt `bytes` unter `path` im Kontext-Baum ab — ein Blob, in den
142 /// bestehenden Baum eingesetzt, als neuer Commit auf dem Ref. Der
143 /// gemeinsame Kern von Session-Ablage und Index-Ablage.
144 fn write_blob_once(
145 &self,
146 path: &str,
147 bytes: &[u8],
148 message: &str,
149 ) -> minds_git::Result<RefUpdate> {
150 let blob = self.repo.write_blob(bytes)?;
151 let base = self.repo.tree_at(&self.reference)?;
152 let tree = self.repo.write_tree(base, [(path, blob)])?;
153 self.repo.commit_tree_to_ref(&self.reference, tree, message)
154 }
155}

157impl ContextStore for GitStore {
158 fn put_bytes(&self, session: &SessionBytes) -> Result<Put> {
159 let path = path_of(session.id());
160
161 // Liegt dort schon genau das? Dann ist nichts zu tun — und zwar
162 // wirklich nichts: kein Objekt, kein Baum, kein Commit. Ein
163 // *abweichender* Inhalt fällt hier durch und wird unten überschrieben;
164 // siehe Modul-Doku.
165 let stored = self
166 .repo
167 .read_blob_at(&self.reference, &path)
168 .map_err(StoreError::backend)?;
169 if stored.as_deref() == Some(session.as_bytes()) {
170 return Ok(Put::AlreadyPresent(session.id()));
171 }
172
173 let mut attempts_left = PUT_ATTEMPTS;
174
175 loop {
176 attempts_left -= 1;
177 match self.write_once(&path, session) {
178 Ok(update) => {
179 return Ok(if update.wrote_commit() {
180 Put::Written(session.id())
181 } else {
182 // Zwischen Nachsehen und Schreiben war jemand schneller
183 // — mit demselben Inhalt. Die untere Schicht hat es
184 // gefangen.
185 Put::AlreadyPresent(session.id())
186 });
187 }
188 // Ein paralleler Lauf war schneller. Verloren ist nichts — der
189 // nächste Versuch liest den neuen Stand und setzt darauf auf.
190 Err(GitError::RefRaced { .. }) if attempts_left > 0 => {}
191 Err(err) => return Err(StoreError::backend(err)),
192 }
193 }
194 }
195
196 fn get_bytes(&self, id: SessionId) -> Result<Option<Vec<u8>>> {
197 self.repo
198 .read_blob_at(&self.reference, &path_of(id))
199 .map_err(StoreError::backend)
200 }
201
202 fn list(&self) -> Result<Vec<SessionId>> {
203 let paths = self
204 .repo
205 .list_blobs_at(&self.reference)
206 .map_err(StoreError::backend)?;
207
208 // Fremde Einträge überspringen statt melden — `index.json` ist ein
209 // vorgesehener Nachbar, kein Defekt (siehe `layout`).
210 let mut ids: Vec<SessionId> = paths
211 .iter()
212 .map(String::as_str)
213 .filter_map(id_of_path)
214 .collect();
215
216 // Nach Pfad sortiert kämen sie ohnehin sortiert an; die Zusage des
217 // Traits soll aber nicht davon abhängen, dass Hex-Sortierung und
218 // Byte-Sortierung zufällig zusammenfallen.
219 ids.sort();
220 Ok(ids)
221 }
222
223 fn get_index_bytes(&self) -> Result<Option<Vec<u8>>> {
224 self.repo
225 .read_blob_at(&self.reference, INDEX_PATH)
226 .map_err(StoreError::backend)
227 }

229 fn put_index_bytes(&self, bytes: &[u8]) -> Result<()> {
230 // Anders als eine Session ist der Index nicht content-adressiert: Zwei
231 // Läufe schreiben verschiedene Inhalte an denselben Pfad. Deshalb kein
232 // „liegt schon so da"-Kurzschluss, aber dieselbe CAS-Retry gegen einen
233 // parallelen Schreiber.
234 let mut attempts_left = PUT_ATTEMPTS;
235 loop {
236 attempts_left -= 1;
237 match self.write_blob_once(INDEX_PATH, bytes, "minds: Index aktualisiert") {
238 Ok(_) => return Ok(()),
239 Err(GitError::RefRaced { .. }) if attempts_left > 0 => {}
240 Err(err) => return Err(StoreError::backend(err)),
241 }
242 }
243 }
244}

Absicht

Ich möchte M5 so umbauen, dass wir es genauso machen wie entire! Mit dem Hook-Ansatz. Wir bleiben erst einmal bei der Rust implementierung. Diese ist effizienter. Das ist der entscheidende Unterschied. Minds soll auch Hooks installieren im Agenten selbst: Claude Code über `.claude/settings.json`, Codex über `.codex/hooks.json`, Cursor über `.cursor/hooks.json`, Gemini über `.gemini/settings.json`, OpenCode über ein TypeScript-Plugin. Bei Codex wird zusätzlich `codex_hooks = true` in die `config.toml` geschrieben. Dazu Git-Hooks: Checkpoints entstehen, wenn du oder der Agent committen; die Session-Metadaten möchte ich entweder auf einem child-repo haben oder falls wir diese kombination nicht haben direkt im repo. Das Verhalten soll an der Stelle absolut gleich sein.
