1//! Test-Fixtures: eine echte redigierte Session und ein echtes Repository.
2//!
3//! # Die Session kommt aus der Pipeline
4//!
5//! Bewusst **keine** handgebaute [`RedactedSession`] — den Typ gibt es nur aus
6//! der Redaction, und genau das soll auch im Test gelten. Ein Fixture, das am
7//! vorgesehenen Weg vorbeibaut, prüft am Ende eine Bauform, die es in Produktion
8//! nicht gibt.
9//!
10//! # Das Repository kommt von `git`
11//!
12//! Dieselbe Begründung wie in `minds-git`: Würden die Fixtures mit gix gebaut
13//! und mit gix gelesen, wären Schreib- und Lesefehler symmetrisch und blieben
14//! unsichtbar. Erst ein von echtem `git` erzeugtes Repo prüft die Frage, auf die
15//! es ankommt — und umgekehrt zeigt erst echtes `git` auf dem Ergebnis, ob das,
16//! was Minds schreibt, gewöhnliches Git ist. Für `cargo test` muss `git` im PATH
17//! liegen; ausgeliefert wird weiterhin ein Binary ohne `git`-Abhängigkeit.
18//!
19//! Jeder Aufruf läuft ohne globale und systemweite Konfiguration und mit fester
20//! Identität und festem Datum, damit nicht die Umgebung des Entwicklers
21//! mitentscheidet (ein gesetztes `commit.gpgsign` reicht sonst für rote Tests,
22//! die mit dem Code nichts zu tun haben).
23//!
24//! # Bar und nicht bar
25//!
26//! [`TempRepo::init`] legt ein Repository mit Arbeitsverzeichnis an (das Repo
27//! des Codes), [`TempRepo::init_bare`] eines ohne (das Kontext-Repo des
28//! Child-Backends — dort arbeitet niemand). Beide bekommen eine **lokale**
29//! Identität: `commit_tree_to_ref` besteht darauf, und die globale ist hier
30//! bewusst abgeklemmt.
31//!
32//! # Doppelung, mit Ablaufdatum
33//!
34//! `minds-git` hat dasselbe `TempRepo`, nur reicher — es ist dort `pub(crate)`
35//! und damit hier nicht erreichbar. Diese schlanke Zweitfassung ist der
36//! Stopgap; spätestens wenn `minds-cli` (M6) und `minds-reader` (M7) sie zum
37//! dritten und vierten Mal brauchen, gehört die Fixture in `minds-git` hinter
38//! ein `testing`-Feature.
39

64 },

69 tool_calls: Vec::new(),
70 parent: None,
71 at: None,

74 RedactionConfig::default()

76 .expect("Default-Pipeline hat Detektoren")
77 .redact_session(session)
78 .expect("harmloser Text läuft sauber durch")
79}

132 /// Wie viele Objekte in der Objektdatenbank liegen — erreichbar oder nicht.

162/// Schreibt Name und E-Mail in die **lokale** Config des Repositories.
163///
164/// Nicht nur in die Umgebung: gix liest die Identität aus der Konfiguration des
165/// Repositories, in das geschrieben wird, und `commit_tree_to_ref` besteht auf
166/// einer. Die Env-Variablen in [`git_in`] sieht nur das `git`-Kind.
167fn configure_identity(repo: &Path) {
168 git_in(repo, &["config", "user.name", "Minds Test"]);

172/// Führt `git` in `dir` aus und gibt stdout zurück; bricht ab, wenn der Aufruf
173/// fehlschlägt.
174fn git_in(dir: &Path, args: &[&str]) -> String {
175 // Ein Pfad, den es nicht gibt: Git behandelt ihn wie eine leere
176 // Konfiguration — portabler als /dev/null.
177 let no_config = dir.join("keine.gitconfig");
178
179 let output = Command::new("git")
180 .args(args)
181 .current_dir(dir)
182 .env("GIT_CONFIG_GLOBAL", &no_config)
183 .env("GIT_CONFIG_SYSTEM", &no_config)
184 .env("GIT_CONFIG_NOSYSTEM", "1")
185 .env("GIT_EDITOR", "true")
186 .env("EDITOR", "true")
187 .env("GIT_AUTHOR_NAME", "Minds Test")
188 .env("GIT_AUTHOR_EMAIL", "test@example.invalid")
189 .env("GIT_COMMITTER_NAME", "Minds Test")
190 .env("GIT_COMMITTER_EMAIL", "test@example.invalid")
191 .env("GIT_AUTHOR_DATE", "2024-01-01T00:00:00+00:00")
192 .env("GIT_COMMITTER_DATE", "2024-01-01T00:00:00+00:00")
193 .output()
194 .expect("`git` muss für die Tests im PATH liegen");
195
196 assert!(
197 output.status.success(),
198 "git {args:?} in {dir:?} fehlgeschlagen:\n{}",
199 String::from_utf8_lossy(&output.stderr)
200 );
201 String::from_utf8(output.stdout).expect("git-Ausgabe ist UTF-8")

Absicht

Ich möchte M5 so umbauen, dass wir es genauso machen wie entire! Mit dem Hook-Ansatz. Wir bleiben erst einmal bei der Rust implementierung. Diese ist effizienter. Das ist der entscheidende Unterschied. Minds soll auch Hooks installieren im Agenten selbst: Claude Code über `.claude/settings.json`, Codex über `.codex/hooks.json`, Cursor über `.cursor/hooks.json`, Gemini über `.gemini/settings.json`, OpenCode über ein TypeScript-Plugin. Bei Codex wird zusätzlich `codex_hooks = true` in die `config.toml` geschrieben. Dazu Git-Hooks: Checkpoints entstehen, wenn du oder der Agent committen; die Session-Metadaten möchte ich entweder auf einem child-repo haben oder falls wir diese kombination nicht haben direkt im repo. Das Verhalten soll an der Stelle absolut gleich sein.
