1//! `minds hook` — die Prozesshülle um [`minds_capture::hook_event`].
2//!
3//! Dieses Modul weiß nichts über Agents, Eventnamen oder Payload-Felder. Es
4//! weiß etwas über **Prozesse**: dass stdin begrenzt gelesen werden muss, dass
5//! ein Panic nicht nach draußen darf, dass der Rückgabewert 0 ist und dass
6//! stdout jemand anderem gehört. Das Formatwissen sitzt in `minds-capture` —
7//! damit stimmt die Abhängigkeitsrichtung aus dem Plan (`capture ← cli`), und
8//! Payload-Fixtures lassen sich testen, ohne einen Prozess zu starten.
9//!
10//! # Die drei Regeln
11//!
12//! **1. Immer Exit 0.** Bei Claude Code bedeutet Exit-Code 2 „blockiere diese
13//! Aktion", und stderr wird dem Modell zurückgegeben. Ein abstürzender
14//! Rekorder, dessen Rückgabewert als Blockade gedeutet wird, macht Arbeit
15//! kaputt. Deshalb: `catch_unwind` um alles, jeder Fehler ins Log, Rückgabewert
16//! unverändert 0 — auch bei fehlendem `--agent`, auch wenn nichts geschrieben
17//! werden konnte.
18//!
19//! **2. Kein Byte auf stdout.** Mehrere Agents deuten stdout des Hooks als
20//! Steuerkanal (JSON-Entscheidungen, injizierter Kontext). Was wir dort
21//! ausgäben, würde als Anweisung gelesen. Diagnose geht in eine Datei, nicht
22//! auf einen Kanal, der jemandem gehört.
23//!
24//! **3. Nichts Teures.** Kein Repository öffnen, keine Konfiguration lesen, kein
25//! Transkript parsen, keine Redaction. Der Hook sucht ein Verzeichnis, schreibt
26//! eine Datei und geht. Alles Übrige passiert beim Checkpoint, wo Latenz
27//! niemandem wehtut.
28//!
29//! # Die eine Ausnahme: die Secretfile-Mauer
30//!
31//! Genau ein Deutungsschritt läuft doch schon hier, weil er *fail-closed* ist
32//! und nicht warten darf: [`secretwall::guard`](minds_capture::secretwall::guard)
33//! prüft bei einem Tool-Event den Pfad und lässt den Inhalt einer
34//! Zugangsdaten-Datei (`​.env`, `id_rsa`, `*.pem`) gar nicht erst ins Journal.
35//! Das ist ein Pfad-Test plus, im seltenen Trefferfall, ein kleiner
36//! JSON-Neubau — billig genug für den heißen Pfad und die einzige Stelle, an
37//! der Weglassen wichtiger ist als Geschwindigkeit.
38
39use std::io::{Read, Write};
40use std::path::PathBuf;
41use std::process::ExitCode;
42
43use minds_capture::{Journal, clock, hook_event, secretwall};
44
45/// Obergrenze für stdin. Ein `PostToolUse`-Payload trägt das Tool-Ergebnis mit
46/// und kann groß sein; unbegrenzt zu lesen hieße, dass ein einzelnes `cat`
47/// einer riesigen Datei uns den Speicher füllt.
48///
49/// Darüber wird abgeschnitten. Das Event geht dabei **nicht** verloren: Der
50/// abgeschnittene Rest ist kein gültiges JSON mehr und wird von
51/// [`hook_event::parse`] als Zeichenkette abgelegt statt verworfen. Ein
52/// unvollständiges Event ist besser als ein OOM im Prozess des Nutzers und
53/// besser als gar keines.
54const MAX_STDIN: u64 = 32 * 1024 * 1024;
55
56/// Führt den Hook aus. Gibt **immer** [`ExitCode::SUCCESS`] zurück.
57///
58/// `agent` ist der Name aus der Hook-Registrierung. Fehlt er, ist das ein
59/// Konfigurationsfehler — und trotzdem kein Grund für einen Rückgabewert
60/// ungleich 0. Ein falsch registrierter Hook darf die Sitzung nicht anders
61/// behandeln als ein kaputter; beides landet im Log.
62pub fn run(agent: Option<&str>, event_override: Option<&str>) -> ExitCode {
63 // Regel 1. Auch ein Panic in unserem eigenen Code darf die Sitzung des
64 // Nutzers nicht beenden.
65 let outcome = std::panic::catch_unwind(|| match agent {
66 Some(agent) => record(agent, event_override),
67 None => Err("minds hook ohne --agent aufgerufen".into()),
68 });
69
70 match outcome {
71 Ok(Ok(())) => {}
72 Ok(Err(err)) => log(&format!("{err:#}")),
73 Err(_) => log("Panic im Hook — Event verworfen"),
74 }
75
76 ExitCode::SUCCESS
77}
78
79fn record(agent: &str, event_override: Option<&str>) -> Result<(), Box<dyn std::error::Error>> {
80 let mut bytes = Vec::new();
81 std::io::stdin().take(MAX_STDIN).read_to_end(&mut bytes)?;
82
83 // Die Uhr liest der Prozess, nicht der Parser: So bleibt `parse` eine reine
84 // Funktion und damit gegen Fixtures testbar.
85 let mut parsed = hook_event::parse(bytes, agent, event_override, clock::now())?;
86
87 // Fail-closed, noch vor dem ersten Byte auf der Platte: Berührt dieses Event
88 // eine Zugangsdaten-Datei, wird ihr Inhalt weggelassen, nicht aufgehoben.
89 secretwall::guard(&mut parsed.event);
90
91 // Das Arbeitsverzeichnis aus dem Payload schlaegt unser eigenes — Agents
92 // starten Hooks nicht zwingend im Projektverzeichnis, und ein Hook, der das
93 // falsche Repository findet, schreibt ins falsche Journal.
94 let start: PathBuf = match parsed.cwd {
95 Some(cwd) => cwd,
96 None => std::env::current_dir()?,
97 };
98
99 Journal::discover(&start)?.append(&parsed.key, parsed.event)?;
100 Ok(())
101}
102
103/// Diagnose — best effort, in eine Datei, nie auf stdout oder stderr.
104///
105/// Schlägt auch das Loggen fehl, ist Schweigen die einzig verbleibende Option.
106/// Ein Rekorder, der lauter wird, je kaputter er ist, macht die Sitzung
107/// unbenutzbar.
108fn log(message: &str) {
109 let Ok(dir) = std::env::current_dir() else {
110 return;
111 };
112 let Ok(journal) = Journal::discover(&dir) else {
113 return;
114 };
115 let Some(base) = journal.root().parent() else {
116 return;
117 };
118 let _ = std::fs::create_dir_all(base);
119
120 if let Ok(mut f) = std::fs::OpenOptions::new()
121 .create(true)
122 .append(true)
123 .open(base.join("hook.log"))
124 {
125 let (at, _) = clock::now();
126 let _ = writeln!(f, "{at} {message}");
127 }
128}

Absicht

Ich möchte M5 so umbauen, dass wir es genauso machen wie entire! Mit dem Hook-Ansatz. Wir bleiben erst einmal bei der Rust implementierung. Diese ist effizienter. Das ist der entscheidende Unterschied. Minds soll auch Hooks installieren im Agenten selbst: Claude Code über `.claude/settings.json`, Codex über `.codex/hooks.json`, Cursor über `.cursor/hooks.json`, Gemini über `.gemini/settings.json`, OpenCode über ein TypeScript-Plugin. Bei Codex wird zusätzlich `codex_hooks = true` in die `config.toml` geschrieben. Dazu Git-Hooks: Checkpoints entstehen, wenn du oder der Agent committen; die Session-Metadaten möchte ich entweder auf einem child-repo haben oder falls wir diese kombination nicht haben direkt im repo. Das Verhalten soll an der Stelle absolut gleich sein.
