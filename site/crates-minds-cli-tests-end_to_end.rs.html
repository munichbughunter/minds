1//! Der Kern-Loop, gegen das echte Binary und ein echtes Git-Repo.
2//!
3//! Das ist der Test, der zählt: Er startet `minds` als Prozess — so, wie ein
4//! Agent und ein Nutzer es täten — und geht den ganzen Weg aus der Definition
5//! of Done: einrichten, Hook-Events aufzeichnen, committen, einchecken, und die
6//! Session sowohl über den Commit (`show`) als auch über eine einzelne Zeile
7//! (`why`) wiederfinden. `fsck` bestätigt am Ende, dass nichts verwaist ist.
8//!
9//! Braucht `git` im Pfad. Fehlt es, überspringt der Test sich selbst, statt
10//! falsch-rot zu werden.

18/// Ein frisch initialisiertes Repo, oder `None`, wenn kein `git` da ist.

20 let dir = tempfile::tempdir().unwrap();

22 if !ok {
23 return None;

26 git(dir.path(), &["config", "user.name", "Minds Test"]);
27 Some(dir)
28}

30fn git(dir: &Path, args: &[&str]) -> Output {
31 Command::new("git")
32 .arg("-C")
33 .arg(dir)
34 .args(args)
35 .output()
36 .expect("git läuft")

39/// Ruft `minds` im Repo auf, optional mit stdin (für `hook`).
40fn minds(dir: &Path, args: &[&str], stdin: Option<&str>) -> Output {
41 use std::io::Write;
42 let mut cmd = Command::new(MINDS);
43 cmd.current_dir(dir).args(args);
44 cmd.stdin(std::process::Stdio::piped());
45 cmd.stdout(std::process::Stdio::piped());
46 cmd.stderr(std::process::Stdio::piped());
47 let mut child = cmd.spawn().expect("minds startet");
48 if let Some(input) = stdin {
49 child
50 .stdin
51 .take()
52 .unwrap()
53 .write_all(input.as_bytes())
54 .unwrap();
55 }
56 child.wait_with_output().expect("minds endet")
57}

59fn stdout(output: &Output) -> String {
60 String::from_utf8_lossy(&output.stdout).into_owned()

63/// Ein Hook-Event, wie es der Agent auf stdin schickt.
64fn event(dir: &Path, body: &str) {
65 let payload = format!(

67 dir.display()
68 );
69 let out = minds(dir, &["hook", "--agent", "claude-code"], Some(&payload));

Absicht

Ich möchte M5 so umbauen, dass wir es genauso machen wie entire! Mit dem Hook-Ansatz. Wir bleiben erst einmal bei der Rust implementierung. Diese ist effizienter. Das ist der entscheidende Unterschied. Minds soll auch Hooks installieren im Agenten selbst: Claude Code über `.claude/settings.json`, Codex über `.codex/hooks.json`, Cursor über `.cursor/hooks.json`, Gemini über `.gemini/settings.json`, OpenCode über ein TypeScript-Plugin. Bei Codex wird zusätzlich `codex_hooks = true` in die `config.toml` geschrieben. Dazu Git-Hooks: Checkpoints entstehen, wenn du oder der Agent committen; die Session-Metadaten möchte ich entweder auf einem child-repo haben oder falls wir diese kombination nicht haben direkt im repo. Das Verhalten soll an der Stelle absolut gleich sein. M5.0 docs: Plan.md — M5 von Transkript-Parsing auf Hooks umgestellt (ADR-0003) M5.1 feat(core): Lineage, Turn.parent/at, ToolCall.effect, Vec<Edge> (additiv) M5.2 feat(capture): JournalEvent + Journal (Datei pro Event, 0600, fsck-fähig) M5.3 feat(cli): minds hook — stdin lesen, anhängen, Exit 0, immer M5.4 feat(capture): Normalisierer Claude Code (SessionStart/Prompt/Tool*/Stop/Subagent*) M5.5 feat(capture): Secretfile-Mauer bei PreToolUse M5.6 feat(capture): Journal + Transkript → Vec<Session> (Turns, Usage, Intent) M5.7 feat(capture): Kanten — Subagent (Observed), Artefakt-Hash, Commit M5.8 feat(cli): minds enable --agent claude-code (settings.json mergen, idempotent) M5.9 test(capture): Fixtures — single, subagent, zwei Agents parallel
