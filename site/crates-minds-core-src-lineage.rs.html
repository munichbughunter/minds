1//! Herkunft, Beziehungen und Beweismittel — wer arbeitete wann, in wessen
2//! Auftrag, und woher wir das wissen.
3//!
4//! Das Envelope aus [`crate::session`] beantwortet „was ist passiert". Dieses
5//! Modul beantwortet „in welcher Ordnung, und wie sicher". Es entstand aus
6//! einer konkreten Anforderung: Claude Code plant, Codex reviewt, Claude Code
7//! implementiert die Review-Punkte. Drei Sessions, drei Agents, eine
8//! Reihenfolge — und keines der drei Transkripte weiß vom jeweils anderen.
9//!
10//! # Die Leitregel: Kanten haben eine Herkunft
11//!
12//! Ein einzelner, ungekennzeichneter Pfeil zwischen zwei Sessions wäre eine
13//! Behauptung, die wir nicht decken können. In einem Record, dessen einziger
14//! Wert seine Nachweisbarkeit ist, ist das der Sündenfall. Jede [`Edge`] trägt
15//! deshalb ein [`Evidence`]: beobachtet, per Inhalts-Hash belegt, von einem
16//! Menschen erklärt oder heuristisch vermutet. Der Reader darf danach „sicher"
17//! von „vermutet" unterscheiden; ohne dieses Feld müsste er alles gleich
18//! behandeln und wäre damit im Zweifel unehrlich.
19//!
20//! # Symbolische Endpunkte, keine `SessionId`
21//!
22//! [`Endpoint::Session`] verweist über `(agent, local_id)` — nicht über eine
23//! [`SessionId`](crate::SessionId). Der Grund ist hart und nicht verhandelbar:
24//! Die `SessionId` ist der Hash des fertigen Envelopes. Zeigte ein Kind per
25//! Hash auf seine Eltern, müsste die Eltern-Session abgeschlossen sein, bevor
26//! das Kind gehasht werden kann — beim Orchestrator, der nach dem Sub-Agenten
27//! weiterläuft, ist sie das nie. Ein Inhalts-Hash kann keine Vorwärtsreferenz
28//! enthalten. Die Auflösung symbolisch → Hash macht der Store-Index beim
29//! Schreiben; sie ist wiederholbar, die Kante selbst ist es nicht.
30//!
31//! # Was hier bewusst *nicht* steht: abgeleitete Kanten
32//!
33//! Dass Codex genau die Bytes gelesen hat, die Claude Code geschrieben hat, ist
34//! eine Aussage über *zwei* Sessions. Ein Adapter sieht immer nur eine. Deshalb
35//! erfasst die Capture-Schicht nur **Beweismittel** — [`Effect`] mit Pfad und
36//! [`ContentHash`] am einzelnen Tool-Call — und die *Ableitung* daraus
37//! ([`EdgeKind::ContinuedFrom`] mit [`Evidence::Content`]) passiert später über
38//! den Store-Index, der beide Sessions kennt.
39//!
40//! Die Trennlinie ist der Grund für den Schnitt: **Beweismittel sind
41//! unwiederbringlich, Ableitungen sind wiederholbar.** Was wir heute nicht
42//! mitschreiben, ist weg. Was wir heute nicht ausrechnen, rechnen wir nächsten
43//! Monat aus — dann sogar besser.
44//!
45//! # Hash-Stabilität
46//!
47//! Alle Felder, die dieses Modul dem Envelope hinzufügt, sind `Option` bzw.
48//! `Vec` mit `skip_serializing_if`. Eine Session ohne Herkunft serialisiert
49//! damit **byte-identisch** wie vor diesem Commit und behält ihre `SessionId`.
50//! Das ist als Test formuliert, nicht bloß als Zusage (siehe
51//! `session::tests::additive_fields_do_not_change_canonical_form`).
52

70/// Woher eine Session stammt: ihre agent-eigene Kennung und ihr Zeitfenster.
71///
72/// Der Namensraum von `local_id` ist **`(Session::agent.name, local_id)`** —
73/// nicht global. Zwei Agents dürfen dieselbe UUID vergeben; das kollidiert
74/// nicht, weil der Agentname immer danebensteht.
75///
76/// Ein früherer Entwurf hatte hier zusätzlich ein `run_id` („der gemeinsame
77/// Lauf"). Das war falsch: Claude Code und Codex laufen in getrennten
78/// Prozessen ohne gemeinsame Klammer. Ein `run_id` wäre entweder erfunden oder
79/// für jede Session verschieden und damit wertlos.
80#[derive(Debug, Clone, PartialEq, Eq, Serialize, Deserialize)]
81pub struct Lineage {
82 /// Die Session-/Thread-Kennung des Agenten (Claude Code: `session_id`).
83 pub local_id: String,
84
85 /// Beginn, RFC 3339 in UTC — **aus dem Transkript bzw. dem Hook-Event**,
86 /// niemals `SystemTime::now()` im Adapter. Sonst wäre der Adapter nicht
87 /// deterministisch und die Fixture-Tests aus M5 nicht schreibbar.
88 #[serde(default, skip_serializing_if = "Option::is_none")]
89 pub started_at: Option<String>,
90
91 /// Ende, gleiche Regel.
92 #[serde(default, skip_serializing_if = "Option::is_none")]
93 pub ended_at: Option<String>,
94
95 /// Arbeitsverzeichnis zum Zeitpunkt der Session.
96 ///
97 /// **Achtung, Redaction:** Dieser Wert enthält in aller Regel einen
98 /// Benutzernamen (`/Users/anna/…`, `/home/anna/…`) und ist damit PII. Die
99 /// Pipeline muss ihn scannen; das ist kein optionales Feld für den
100 /// Feldlauf.
101 #[serde(default, skip_serializing_if = "Option::is_none")]
102 pub cwd: Option<String>,
103}

121//
122// Zeitpunkte stehen im Envelope als schlichter `String` (RFC 3339, UTC).
123//
124// Ein validierender Newtype wäre verlockend, wäre hier aber schlechter: Eine
125// reine Formprüfung ohne echten Parser gäbe falsche Sicherheit, und ein echter
126// Parser hieße eine Datums-Dependency in `minds-core` — einem Crate, das
127// bewusst nur `serde` und `blake3` kennt und kein I/O hat.
128//
129// Daraus folgt eine Regel, die *nicht* aus dem Typsystem kommt und deshalb hier
130// stehen muss: **Zeitstempel werden nie per String-Vergleich sortiert.** Das
131// wäre nur bei durchnormalisiertem Format korrekt (gleiche Nachkommastellen,
132// immer `Z`), und normalisiert ist hier nichts — was der Agent liefert, wird
133// treu übernommen. Die Ordnungsrelation gehört in die Ableitungsschicht und
134// parst dort richtig.

232/// Was ein Tool-Call in der Welt getan hat, normalisiert.
233///
234/// Zwei Schulden auf einmal:
235///
236/// 1. `minds-redact::secretfile` kündigt seit M2 an, dass die Mauer vor
237/// Zugangsdaten-Dateien „in `minds-capture` durchgesetzt" wird — dafür
238/// braucht der Adapter den Pfad als normalisiertes Feld, nicht vergraben im
239/// agent-spezifischen `arguments`-String.
240/// 2. Die Übergabe zwischen zwei Agents wird über `path` + `content`
241/// nachrechenbar (siehe [`Evidence::Content`]).
242#[derive(Debug, Clone, PartialEq, Eq, Serialize, Deserialize)]
243pub struct Effect {
244 /// Art des Zugriffs.
245 pub kind: EffectKind,
246
247 /// Betroffener Pfad, repo-relativ wo möglich.
248 #[serde(default, skip_serializing_if = "Option::is_none")]
249 pub path: Option<String>,
250
251 /// blake3 über die **Rohbytes** des Gelesenen bzw. Geschriebenen.
252 ///
253 /// Zwei Regeln, die beide fail-closed sind:
254 ///
255 /// - Der Hash wird **vor** der Redaction gebildet. Danach gebildet würde er
256 /// nie matchen, und die ganze Kante wäre tot.
257 /// - Für Dateien, die die Secretfile-Mauer trifft (`.env`, `id_rsa`,
258 /// `*.pem`), wird er **nicht** gebildet. Bei einer kurzen, ratbaren Datei
259 /// wäre ein Hash ein Orakel — man probiert Kandidaten durch, bis es
260 /// passt. Fail-closed gilt auch für Fingerabdrücke.
261 #[serde(default, skip_serializing_if = "Option::is_none")]
262 pub content: Option<ContentHash>,
263}

284/// blake3 über einen Byte-Strom, in derselben Textform wie
285/// [`SessionId`](crate::SessionId): `b3-` plus 64 Hex-Zeichen, klein
286/// geschrieben.
287///
288/// Eigener Typ statt `SessionId`, obwohl das Format identisch ist: Ein
289/// Datei-Inhalt ist keine Session. Die beiden zu vermischen hieße, dass man sie
290/// versehentlich vergleichen oder verwechseln kann — und der Store könnte einen
291/// Datei-Hash als Session-Referenz auflösen wollen.
292///
293/// **Lesen tolerant, Schreiben kanonisch** (wie im restlichen Crate): [`FromStr`]
294/// akzeptiert Groß- und Kleinschreibung sowie ein fehlendes Präfix,
295/// [`fmt::Display`] gibt ausschließlich die kanonische Form aus.
296///
297/// # Verhältnis zur Redaction
298///
299/// Eine berechtigte Sorge: Frisst der `HighEntropyRedactor` unsere eigenen
300/// Hashes? Nein — Hex trägt höchstens 4 bit pro Zeichen und bleibt damit unter
301/// der Entropieschwelle. Genau dieser Fall ist in
302/// `minds-redact::session` bereits als Begründung dafür dokumentiert, warum die
303/// Ausnahmeliste leer bleiben darf.
304#[derive(Debug, Clone, PartialEq, Eq, Hash, PartialOrd, Ord, Serialize, Deserialize)]
305#[serde(try_from = "String", into = "String")]
306pub struct ContentHash(String);
307
308impl ContentHash {
309 /// Aus 32 Rohbytes (der üblichen blake3-Ausgabe).
310 pub fn from_bytes(digest: [u8; 32]) -> Self {
311 let mut s = String::with_capacity(CONTENT_HASH_PREFIX.len() + HEX_LEN);
312 s.push_str(CONTENT_HASH_PREFIX);
313 for b in digest {
314 // Kleinbuchstaben, feste Breite — die kanonische Form.
315 s.push(char::from_digit((b >> 4) as u32, 16).expect("nibble"));
316 s.push(char::from_digit((b & 0x0f) as u32, 16).expect("nibble"));
317 }
318 Self(s)
319 }
320
321 /// Der Hex-Anteil ohne Präfix.
322 pub fn hex(&self) -> &str {
323 &self.0[CONTENT_HASH_PREFIX.len()..]
324 }
325
326 /// Die kanonische Textform mit Präfix.
327 pub fn as_str(&self) -> &str {
328 &self.0
329 }
330}
331

333 fn fmt(&self, f: &mut fmt::Formatter<'_>) -> fmt::Result {

336}

352impl FromStr for ContentHash {
353 type Err = ContentHashParseError;
354
355 fn from_str(s: &str) -> Result<Self, Self::Err> {
356 // Praefix case-insensitiv abstreifen (`b3-` wie `B3-`), damit „Lesen
357 // tolerant" auch fuer die Grossschreibung gilt. Ein blosser Hex-String
358 // ohne Praefix bleibt unberuehrt: Seine ersten drei Zeichen koennen
359 // `b3-` nie gleichen, weil Hex kein `-` enthaelt.
360 let hex = match s.get(..CONTENT_HASH_PREFIX.len()) {
361 Some(p) if p.eq_ignore_ascii_case(CONTENT_HASH_PREFIX) => {
362 &s[CONTENT_HASH_PREFIX.len()..]
363 }
364 _ => s,
365 };
366 if hex.len() != HEX_LEN {
367 return Err(ContentHashParseError::Length(hex.len()));
368 }
369 if let Some(c) = hex.chars().find(|c| !c.is_ascii_hexdigit()) {
370 return Err(ContentHashParseError::NotHex(c));
371 }
372 Ok(Self(format!(
373 "{CONTENT_HASH_PREFIX}{}",
374 hex.to_ascii_lowercase()
375 )))
376 }
377}

Absicht

Ich möchte M5 so umbauen, dass wir es genauso machen wie entire! Mit dem Hook-Ansatz. Wir bleiben erst einmal bei der Rust implementierung. Diese ist effizienter. Das ist der entscheidende Unterschied. Minds soll auch Hooks installieren im Agenten selbst: Claude Code über `.claude/settings.json`, Codex über `.codex/hooks.json`, Cursor über `.cursor/hooks.json`, Gemini über `.gemini/settings.json`, OpenCode über ein TypeScript-Plugin. Bei Codex wird zusätzlich `codex_hooks = true` in die `config.toml` geschrieben. Dazu Git-Hooks: Checkpoints entstehen, wenn du oder der Agent committen; die Session-Metadaten möchte ich entweder auf einem child-repo haben oder falls wir diese kombination nicht haben direkt im repo. Das Verhalten soll an der Stelle absolut gleich sein. M5.0 docs: Plan.md — M5 von Transkript-Parsing auf Hooks umgestellt (ADR-0003) M5.1 feat(core): Lineage, Turn.parent/at, ToolCall.effect, Vec<Edge> (additiv) M5.2 feat(capture): JournalEvent + Journal (Datei pro Event, 0600, fsck-fähig) M5.3 feat(cli): minds hook — stdin lesen, anhängen, Exit 0, immer M5.4 feat(capture): Normalisierer Claude Code (SessionStart/Prompt/Tool*/Stop/Subagent*) M5.5 feat(capture): Secretfile-Mauer bei PreToolUse M5.6 feat(capture): Journal + Transkript → Vec<Session> (Turns, Usage, Intent) M5.7 feat(capture): Kanten — Subagent (Observed), Artefakt-Hash, Commit M5.8 feat(cli): minds enable --agent claude-code (settings.json mergen, idempotent) M5.9 test(capture): Fixtures — single, subagent, zwei Agents parallel

Absicht

Ich möchte M5 so umbauen, dass wir es genauso machen wie entire! Mit dem Hook-Ansatz. Wir bleiben erst einmal bei der Rust implementierung. Diese ist effizienter. Das ist der entscheidende Unterschied. Minds soll auch Hooks installieren im Agenten selbst: Claude Code über `.claude/settings.json`, Codex über `.codex/hooks.json`, Cursor über `.cursor/hooks.json`, Gemini über `.gemini/settings.json`, OpenCode über ein TypeScript-Plugin. Bei Codex wird zusätzlich `codex_hooks = true` in die `config.toml` geschrieben. Dazu Git-Hooks: Checkpoints entstehen, wenn du oder der Agent committen; die Session-Metadaten möchte ich entweder auf einem child-repo haben oder falls wir diese kombination nicht haben direkt im repo. Das Verhalten soll an der Stelle absolut gleich sein.
