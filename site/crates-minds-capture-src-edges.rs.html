1//! Kanten — die Beziehungen einer Session, jede mit ihrer Herkunft.
2//!
3//! Das Envelope beantwortet „was ist passiert". [`Edge`] beantwortet „in welcher
4//! Ordnung, und wie sicher". Die Leitregel aus [`minds_core`] gilt streng: Eine
5//! Kante ohne [`Evidence`] wäre eine Behauptung, die wir nicht decken können.
6//! Dieses Modul erzeugt deshalb ausschließlich Kanten, die aus den **eigenen
7//! beobachteten Events** einer Session folgen — nie aus einer Vermutung über
8//! eine andere.
9//!
10//! # Drei Sorten, drei Quellen
11//!
12//! - **Sub-Agent** ([`EdgeKind::Spawned`]/[`EdgeKind::SpawnedBy`],
13//! [`Evidence::Observed`]): Ein Hook-Event hat es gesehen. Der Elternteil
14//! sieht seinen `SubagentStart`/`SubagentEnd`, das Kind sieht seinen eigenen
15//! Start als Sub-Agent. Jede Richtung wird aus der Session gegründet, in deren
16//! Journal sie steht — nie über Kreuz geraten.
17//! - **Commit** ([`EdgeKind::Produced`], [`Evidence::Observed`]): Der
18//! post-commit-Hook ruft den Checkpoint mit dem gerade entstandenen Commit
19//! auf. Dass *diese* Session *diesen* Commit erzeugt hat, ist damit beobachtet,
20//! nicht geschlossen.
21//!
22//! # Was hier bewusst *nicht* steht: die Übergabe-Kante
23//!
24//! [`EdgeKind::ContinuedFrom`] mit [`Evidence::Content`] („Codex las genau die
25//! Bytes, die Claude schrieb") ist eine Aussage über *zwei* Sessions. Ein
26//! Checkpoint sieht immer nur eine. Diese Kante entsteht später im Store-Index,
27//! der beide kennt — hier wird nur das Beweismittel dafür gelegt: der
28//! Inhalts-Hash am [`Effect`](minds_core::Effect), den der Adapter beim
29//! Checkpoint bildet.
30

36/// Die Kante zum Commit, den dieser Checkpoint begleitet.
37pub fn commit(commit_id: &str) -> Edge {
38 Edge {
39 kind: EdgeKind::Produced,
40 to: Endpoint::Commit {
41 id: commit_id.to_string(),
42 },
43 evidence: Evidence::Observed,
44 }
45}

47/// Sub-Agent-Kanten, aus den Events *dieser* Session gegründet.
48///
49/// `agent` ist der Name der aktuellen Session; er füllt die Lücke, wenn der
50/// Payload den Agenten der Gegenseite nicht nennt (der Regelfall bei einem
51/// Sub-Agenten desselben Agenten).
52///
53/// Zwei Richtungen, beide beobachtet:
54/// - Nennt ein `SubagentStart`/`SubagentEnd` ein Kind, entsteht [`Spawned`].
55/// - Nennt der Sessionstart einen Elternteil, entsteht [`SpawnedBy`].
56///
57/// [`Spawned`]: EdgeKind::Spawned
58/// [`SpawnedBy`]: EdgeKind::SpawnedBy
59pub fn subagent(agent: &str, events: &[JournalEvent]) -> Vec<Edge> {
60 let mut edges = Vec::new();
61
62 for event in events {
63 let Ok(marker) = serde_json::from_str::<SubagentMarker>(event.payload.get()) else {
64 continue;
65 };
66
67 match event.kind {
68 EventKind::SubagentStart | EventKind::SubagentEnd => {
69 if let Some(child) = marker.child(agent) {
70 push_unique(
71 &mut edges,
72 Edge {
73 kind: EdgeKind::Spawned,
74 to: child,
75 evidence: Evidence::Observed,
76 },
77 );
78 }
79 }
80 EventKind::SessionStart => {
81 if let Some(parent) = marker.parent(agent) {
82 push_unique(
83 &mut edges,
84 Edge {
85 kind: EdgeKind::SpawnedBy,
86 to: parent,
87 evidence: Evidence::Observed,
88 },
89 );
90 }
91 }
92 _ => {}
93 }
94 }
95
96 edges
97}
98
99/// Fügt eine Kante nur hinzu, wenn sie nicht schon da ist — mehrere
100/// `SubagentEnd` für dasselbe Kind ergeben eine Kante, nicht drei.
101fn push_unique(edges: &mut Vec<Edge>, edge: Edge) {
102 if !edges.contains(&edge) {
103 edges.push(edge);
104 }
105}

107/// Die Felder, mit denen ein Hook-Event eine Sub-Agent-Beziehung benennen kann.
108///
109/// Bewusst tolerant: Der Agent der Gegenseite ist optional (ein Sub-Agent
110/// desselben Agenten nennt ihn nicht), und fehlt die Kennung ganz, entsteht
111/// keine Kante — geraten wird nicht.
112#[derive(Debug, Default, Deserialize)]
113struct SubagentMarker {
114 subagent_session_id: Option<String>,
115 subagent_agent: Option<String>,
116 parent_session_id: Option<String>,
117 parent_agent: Option<String>,
118}
119
120impl SubagentMarker {
121 /// Der Endpunkt des Kindes, falls benannt. `default_agent` springt ein, wenn
122 /// der Payload keinen eigenen nennt.
123 fn child(&self, default_agent: &str) -> Option<Endpoint> {
124 self.subagent_session_id
125 .clone()
126 .map(|local_id| Endpoint::Session {
127 agent: self
128 .subagent_agent
129 .clone()
130 .unwrap_or_else(|| default_agent.to_string()),
131 local_id,
132 })
133 }
134
135 /// Der Endpunkt des Elternteils, falls benannt.
136 fn parent(&self, default_agent: &str) -> Option<Endpoint> {
137 self.parent_session_id
138 .clone()
139 .map(|local_id| Endpoint::Session {
140 agent: self
141 .parent_agent
142 .clone()
143 .unwrap_or_else(|| default_agent.to_string()),
144 local_id,
145 })
146 }
147}

Absicht

Ich möchte M5 so umbauen, dass wir es genauso machen wie entire! Mit dem Hook-Ansatz. Wir bleiben erst einmal bei der Rust implementierung. Diese ist effizienter. Das ist der entscheidende Unterschied. Bei Codex wird zusätzlich `codex_hooks = true` in die `config.toml` geschrieben. Dazu Git-Hooks: Checkpoints entstehen, wenn du oder der Agent committen; die Session-Metadaten möchte ich entweder auf einem child-repo haben oder falls wir diese kombination nicht haben direkt im repo. Das Verhalten soll an der Stelle absolut gleich sein. Ich möchte M5 so umbauen, dass wir es genauso machen wie entire! Mit dem Hook-Ansatz. Wir bleiben erst einmal bei der Rust implementierung. Diese ist effizienter. Das ist der entscheidende Unterschied. Minds soll auch Hooks installieren im Agenten selbst: Claude Code über `.claude/settings.json`, Codex über `.codex/hooks.json`, Cursor über `.cursor/hooks.json`, Gemini über `.gemini/settings.json`, OpenCode über ein TypeScript-Plugin. Bei Codex wird zusätzlich `codex_hooks = true` in die `config.toml` geschrieben. Dazu Git-Hooks: Checkpoints entstehen, wenn du oder der Agent committen; die Session-Metadaten möchte ich entweder auf einem child-repo haben oder falls wir diese kombination nicht haben direkt im repo. Das Verhalten soll an der Stelle absolut gleich sein. M5.0 docs: Plan.md — M5 von Transkript-Parsing auf Hooks umgestellt (ADR-0003) M5.1 feat(core): Lineage, Turn.parent/at, ToolCall.effect, Vec<Edge> (additiv) M5.2 feat(capture): JournalEvent + Journal (Datei pro Event, 0600, fsck-fähig) M5.3 feat(cli): minds hook — stdin lesen, anhängen, Exit 0, immer M5.4 feat(capture): Normalisierer Claude Code (SessionStart/Prompt/Tool*/Stop/Subagent*) M5.5 feat(capture): Secretfile-Mauer bei PreToolUse M5.6 feat(capture): Journal + Transkript → Vec<Session> (Turns, Usage, Intent) M5.7 feat(capture): Kanten — Subagent (Observed), Artefakt-Hash, Commit M5.8 feat(cli): minds enable --agent claude-code (settings.json mergen, idempotent) M5.9 test(capture): Fixtures — single, subagent, zwei Agents parallel
