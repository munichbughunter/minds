1//! `minds checkpoint` — der kalte Pfad, den der post-commit-Hook aufruft.
2//!
3//! Hier schließt sich der Kern-Loop: Das Journal, das `minds hook` heiß und roh
4//! gefüllt hat, wird gedeutet, redigiert, gespeichert und über einen
5//! Commit-Trailer mit dem Code verbunden.
6//!
7//! ```text
8//! Journal ──► adapter::checkpoint ──► Redaction ──► Store ──► Trailer an HEAD
9//! (roh) (Session) (fail-closed) (b3-…) (Minds-Session-Id)
10//! ```
11//!
12//! # Der Trailer, nicht die Produced-Kante
13//!
14//! Der Verweis Commit → Session steht als **Trailer in der Commit-Message** —
15//! nicht am Hash. Nur so übersteht er Rebase, Squash und Cherry-Pick
16//! (Architektur-Prinzip 1). Ihn nachzurüsten heißt aber, die Message zu ändern,
17//! und die Message ist Teil des Commit-Objekts: Der Commit wird umgeschrieben
18//! (siehe [`Repo::amend_head_with_sessions`]).
19//!
20//! Genau deshalb trägt die hier gebaute Session **keine Produced-Kante**. Sie
21//! zeigte auf den Commit *vor* dem Nachrüsten — den, den das Amend verwaist und
22//! den `git gc` irgendwann einsammelt. Eine Kante, die ins Leere zeigen kann,
23//! wäre in einem Record, dessen Wert seine Nachweisbarkeit ist, das Gegenteil
24//! von hilfreich. Der Trailer ist die belastbare Richtung (Commit → Session);
25//! die Kante Session → Commit bleibt der Adapter-Fähigkeit für Abläufe
26//! vorbehalten, in denen der Commit feststeht (Store-Index, späteres `minds
27//! link`).
28//!
29//! # Robust gegen die eine schlechte Session
30//!
31//! Scheitert eine Session (Redaction bricht ab, der Store nimmt sie nicht), wird
32//! *nur sie* übersprungen und ihr Journal **nicht** verworfen — sie bleibt für
33//! den nächsten Lauf und für `minds fsck` sichtbar. Die übrigen Sessions laufen
34//! trotzdem durch. Eine vergiftete Session darf den Checkpoint der anderen nicht
35//! mitreißen.
36//!
37//! # `--commit` als Wächter
38//!
39//! Der post-commit-Hook reicht den gerade entstandenen Commit als `--commit`
40//! herein. Steht HEAD noch dort, wird nachgerüstet; ist HEAD inzwischen
41//! weitergewandert (ein zweiter Commit kam dazwischen), werden die Sessions zwar
42//! gespeichert, aber **nicht** an den falschen Commit getrailert — dann fehlt
43//! nur der Verweis, und `minds fsck` meldet die Waise, statt dass ein falscher
44//! entsteht.
45

57type Fallible<T> = std::result::Result<T, Box<dyn std::error::Error>>;

59/// Führt `minds checkpoint` aus. `commit` ist der Wächter-Commit aus dem
60/// post-commit-Hook (siehe Modul-Doku); ohne ihn wird HEAD nachgerüstet, sofern
61/// vorhanden.
62pub fn run(commit: Option<&str>) -> ExitCode {
63 match checkpoint(commit) {
64 Ok(()) => ExitCode::SUCCESS,
65 Err(err) => {
66 eprintln!("minds checkpoint: {err}");
67 ExitCode::FAILURE
68 }
69 }
70}

72fn checkpoint(commit: Option<&str>) -> Fallible<()> {
73 let cwd = std::env::current_dir()?;
74 let repo = Repo::discover(&cwd)?;
75 let root = repo_root(&repo);
76
77 let store = config::load(&root).open(&root)?;
78 let journal = Journal::open(repo.git_dir());
79 let pipeline = RedactionConfig::default().pipeline()?;
80
81 let mut stored: Vec<SessionId> = Vec::new();
82 for key in journal.sessions()? {
83 let events = journal.read(&key)?.events;
84 if events.is_empty() {
85 continue;
86 }
87
88 match store_one(&key, &events, &root, &pipeline, store.as_ref()) {
89 Ok(id) => {
90 // Erst nach erfolgreicher Ablage verwerfen: Ein Absturz dazwischen
91 // darf Rohdaten nicht verlieren.
92 journal.discard(&key)?;
93 println!(" {}/{}: {id}", key.agent(), key.local_id());
94 stored.push(id);
95 }
96 Err(err) => {
97 // Journal bleibt liegen — die Session ist nicht verloren, nur
98 // vertagt. fsck macht sie sichtbar.
99 eprintln!(" {}/{}: übersprungen ({err})", key.agent(), key.local_id());
100 }
101 }
102 }
103
104 attach_trailers(&repo, commit, &stored)
105}

107/// Baut eine Session, redigiert sie und legt sie ab. Gibt ihre [`SessionId`]
108/// zurück.
109fn store_one(
110 key: &minds_capture::SessionKey,
111 events: &[minds_capture::JournalEvent],
112 root: &Path,
113 pipeline: &minds_redact::RedactionPipeline,
114 store: &dyn ContextStore,
115) -> Fallible<SessionId> {
116 // Kein Commit im Kontext: die Produced-Kante bliebe sonst am verwaisten
117 // Vor-Amend-Commit hängen (siehe Modul-Doku). Der Artefakt-Hash braucht die
118 // Repo-Wurzel, um relative Pfade aufzulösen.
119 let ctx = Checkpoint {
120 root: Some(root),
121 commit: None,
122 };
123 let session = adapter::checkpoint(key, events, &ctx);
124 let redacted = pipeline.redact_session(session)?;
125 let put = store.put(&redacted)?;
126 Ok(put.id())
127}

129/// Rüstet die Trailer an HEAD nach — aber nur, wenn HEAD noch auf dem
130/// Wächter-Commit steht.
131fn attach_trailers(repo: &Repo, commit: Option<&str>, sessions: &[SessionId]) -> Fallible<()> {
132 if sessions.is_empty() {
133 return Ok(());
134 }
135
136 if let Some(expected) = commit {
137 let expected: CommitId = expected.parse()?;
138 if repo.head()?.commit() != Some(expected) {
139 eprintln!(
140 " HEAD steht nicht mehr auf {expected}; {} Session(s) gespeichert, aber nicht getrailert",
141 sessions.len()
142 );
143 return Ok(());
144 }
145 }
146
147 let update = repo.amend_head_with_sessions(sessions)?;
148 if update.rewrote_head() {
149 println!(" Trailer an {} nachgerüstet", update.commit());
150 }
151 Ok(())
152}

154/// Die Repo-Wurzel: das Elternverzeichnis von `.git`. Für ein bares Repo (kein
155/// Elternteil) fällt sie auf das Git-Verzeichnis selbst zurück.
156fn repo_root(repo: &Repo) -> std::path::PathBuf {
157 repo.git_dir()
158 .parent()
159 .unwrap_or_else(|| repo.git_dir())
160 .to_path_buf()

Absicht

Ich möchte M5 so umbauen, dass wir es genauso machen wie entire! Mit dem Hook-Ansatz. Wir bleiben erst einmal bei der Rust implementierung. Diese ist effizienter. Das ist der entscheidende Unterschied. Minds soll auch Hooks installieren im Agenten selbst: Claude Code über `.claude/settings.json`, Codex über `.codex/hooks.json`, Cursor über `.cursor/hooks.json`, Gemini über `.gemini/settings.json`, OpenCode über ein TypeScript-Plugin. Bei Codex wird zusätzlich `codex_hooks = true` in die `config.toml` geschrieben. Dazu Git-Hooks: Checkpoints entstehen, wenn du oder der Agent committen; die Session-Metadaten möchte ich entweder auf einem child-repo haben oder falls wir diese kombination nicht haben direkt im repo. Das Verhalten soll an der Stelle absolut gleich sein.
