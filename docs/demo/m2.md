# Demo M2: Agent → Checkpoint → Binding → Pre-Push → Evidence → Server → Quittung → unabhängiges Verify

Stand 2026-10-28, minds 0.5.0 (Spec S3-MVP v0.3.7, Commit 8). Manueller
End-to-End-Durchstich mit **getrenntem Witness**, **Server-Witness im
Pilotbetrieb** und **unabhängigem Prüfer** aus einem frischen Clone. Die
Ausgaben unten sind aus dem Lauf vom 28.10.2026 (Linux, Ubuntu 24.04, git
2.43, OpenSSH 9.6); Ids und Zeiten sind bei jedem Lauf andere.

Drei Kennungen, drei Vertrauensgrenzen:

| Kennung | Rolle | Was sie nicht kann |
| --- | --- | --- |
| `agent` | Entwickler und Coding-Agent (dieselbe Kennung) | Witness-Home lesen, Server-Schlüssel lesen, `refs/minds/witness/*` schreiben, `/etc/minds/receipt-keys` ändern |
| `minds-witness` | geschützter Witness (eigene Kennung, Binary root-eigen, Home privat) | — |
| `minds-git` | Git-Server mit `minds-witness-hook` (pre-/post-receive), hält den Signierschlüssel | — |
| `pruefer` | unabhängiger Prüfer, frischer Clone | — |

Push und Fetch laufen über `sudo -u minds-git git-receive-pack|git-upload-pack`
— dieselbe Trennung wie ein Git-Server per SSH unter eigener Kennung (Spec §8
nennt `ssh localhost`; das geht genauso, braucht aber einen SSH-Dienst).

Szenarien und Ergebnis des Laufs:

| # | Was | Erwartet | Ergebnis |
| --- | --- | --- | --- |
| 1 | Agent ändert `a`, `b`; Push (Observe) | `Verified, 2/2`, verify Exit 0 | ✓ |
| 2a | Agent `a`, `b`, Entwickler `c` **im Worktree** von Hand | `Verified, 3/3` (der Witness sah auch `c`) | ✓ |
| 2b | Agent `a`, `b`, `c` **am Witness vorbei** (nur Index) | Push angenommen, Warnung `Partial, 2/3`, verify Exit 2 | ✓ |
| 3 | wie 2b, Policy **Strict Enforce** für `main` | Push abgelehnt, keine Quittung, `main` unverändert | ✓ |
| 3b | `c` beobachtet nachgeholt, Amend, Push (Enforce) | angenommen, `Verified, 3/3`, Exit 0 | ✓ |
| 4 | Evidence-Übertragung scheitert (Server lehnt die Bindung ab) | Code-Push geht durch, `Unverified`, Exit 2 (s3_22) | ✓ |
| 5 | Gegenproben: falsches/fehlendes Projekt, Agent-Schlüssel in git config, Agent schreibt Quittungs-Ref | Exit 1 / 3 / 1, Push abgelehnt | ✓ |

> **Wichtig für Szenario 2:** Der Witness bezeugt **Inhalt im beobachteten
> Worktree**, nicht Autorschaft. Eine Handänderung im Worktree sieht er wie
> jede andere (2a: `3/3`). `Partial` entsteht nur für Inhalt, den er nie gesehen
> hat — hier per `git update-index` direkt in den Index (2b). Die Annahme aus
> Spec §8 („Entwickler ändert eine dritte Datei von Hand → Partial“) gilt
> deshalb nicht; die Demo verwendet 2b.

## Teil 0 · Einrichtung (einmalig, als root bzw. mit `sudo`)

### 0.1 Kennungen und Binaries

```sh
for u in agent minds-git pruefer; do id $u >/dev/null 2>&1 || useradd -m -s /bin/bash $u; done
# Release-Build (Debug-Builds sind größer als die 256 MiB, die der geschützte
# Witness kopiert; notfalls `strip`):
cargo build --release --bin minds --bin minds-witness-hook
install -m 0755 -o root -g root target/release/minds              /usr/local/bin/minds
install -m 0755 -o root -g root target/release/minds-witness-hook /usr/local/bin/minds-witness-hook
install -m 0755 -o root -g root docs/demo/m2-agent.sh             /usr/local/bin/m2-agent
apt-get install -y acl        # setfacl, für die Freigabe des Repos an den Witness
```

### 0.2 Server-Zugang ohne SSH (die Rolle eines Git-Servers)

```sh
cat > /etc/sudoers.d/minds-demo-server <<'EOF'
agent   ALL=(minds-git) NOPASSWD: /usr/bin/git-receive-pack /home/minds-git/demo.git, /usr/bin/git-upload-pack /home/minds-git/demo.git
pruefer ALL=(minds-git) NOPASSWD: /usr/bin/git-upload-pack /home/minds-git/demo.git
EOF
chmod 0440 /etc/sudoers.d/minds-demo-server && visudo -cf /etc/sudoers.d/minds-demo-server
```

### 0.3 Nur in einem Container ohne systemd

`minds enable` richtet den Witness als systemd-Dienst ein. Ist PID 1 nicht
systemd (`ps -p 1 -o comm=`), startet ein Ersatz unter `/usr/sbin/systemctl`
genau die Unit, die `enable` schreibt, unter ihrem `User=` (Inhalt:
[`m2-systemctl-shim.sh`](m2-systemctl-shim.sh)). Auf einem echten Linux und auf
dem Mac (launchd) entfällt dieser Schritt.

```sh
install -m 0755 -o root -g root docs/demo/m2-systemctl-shim.sh /usr/sbin/systemctl
```

## Teil 1 · Repo, geschützter Witness, Server

### 1.1 Server-Repository (als `minds-git`)

```sh
sudo -iu minds-git sh -c 'chmod 0750 ~ && git init -q --bare -b main demo.git && git -C demo.git config receive.fsckObjects true'
```

### 1.2 Repository des Agenten (als `agent`)

```sh
sudo -iu agent sh -c '
set -e; mkdir demo && cd demo && git init -q -b main
git config user.name "Agent Demo"; git config user.email agent@example.invalid
mkdir src; for f in a b c; do printf "fn $f() {}\n" > src/$f.rs; done
git add . && git commit -qm "chore: Gerüst"
git remote add origin /home/minds-git/demo.git
git config remote.origin.receivepack "sudo -n -u minds-git /usr/bin/git-receive-pack"
git config remote.origin.uploadpack  "sudo -n -u minds-git /usr/bin/git-upload-pack"
git push -q origin main'
```

### 1.3 Geschützter Witness — die eine Erhöhung

Der Agent braucht dafür einmal `sudo` (am Mac: das Passwort). Im Container
dafür kurz eine NOPASSWD-Regel, danach sofort weg:

```sh
echo 'agent ALL=(ALL) NOPASSWD: ALL' > /etc/sudoers.d/minds-demo-elevate && chmod 0440 /etc/sudoers.d/minds-demo-elevate
sudo -iu agent sh -c 'cd ~/demo && MINDS_WITNESS=protected minds enable --agent claude-code --project git.example.test/project-42'
rm /etc/sudoers.d/minds-demo-elevate
```

```text

minds: protected witness binds commits for project git.example.test/project-42

minds: witness signers line — it vouches that this witness runs separated (an auditor keeps it in a file of their own, outside the repository):
  minds-witness-user@vm namespaces="minds-witness" ssh-ed25519 AAAAC3NzaC1lZDI1NTE5AAAAIDa1lgeTqu85cnM+hkS6kZQsejjNZ3BXfqQCM54VtExC

```

Danach (neue Anmeldung, also neue Gruppe) **ohne** `--project`:

```sh
sudo -iu agent sh -c 'cd ~/demo && minds enable --agent claude-code && git config minds.project git.example.test/project-42 \
  && git add .claude && git commit -qm "chore: minds hooks" && git push -q origin main && minds doctor'
```


### 1.4 Server-Witness im Pilotbetrieb (als `minds-git`)

Die Signer-Datei des Servers trägt **genau** die Witness-Zeile aus 1.3;
`require_separated_witness = true`, Principal `minds-witness-user@…`.

```sh
LINE=$(grep minds-witness-user@ /home/agent/.config/minds/allowed_signers)
sudo -iu minds-git sh -c "
set -e; umask 077; mkdir -p witness/state && chmod 700 witness witness/state
head -c 32 /dev/urandom | od -An -tx1 | tr -d ' \n' > witness/seed.hex; echo >> witness/seed.hex
printf '%s\n' '$LINE' > witness/allowed_signers; chmod 644 witness/allowed_signers"
sudo -iu minds-git tee witness/hook.json >/dev/null <<'EOF'
{
  "operation": "pilot",
  "project": "git.example.test/project-42",
  "repository": "/home/minds-git/demo.git",
  "state_dir": "/home/minds-git/witness/state",
  "signers_file": "/home/minds-git/witness/allowed_signers",
  "allowed_witness_principals": ["minds-witness-user@vm"],
  "require_separated_witness": true,
  "ssh_keygen": "/usr/bin/ssh-keygen",
  "git": "/usr/bin/git",
  "seed_file": "/home/minds-git/witness/seed.hex",
  "key_valid_from": "2026-10-01T00:00:00Z",
  "policy": {"mode": "observe", "evaluate_refs": ["refs/heads/*"], "enforce_refs": [],
             "max_commits_per_push": 500, "uncovered_cap": 20, "coverage_threshold_percent": 100,
             "pusher_mode": "plain", "pusher_salt": "", "version": 1}
}
EOF
sudo -iu minds-git /usr/local/bin/minds-witness-hook install witness/hook.json   # minds-witness: Hooks installiert
```

(`principal` an die eigene Witness-Zeile anpassen, `@vm` ist der Rechnername.)

## Teil 2 · Szenario 1: `Verified`

### 2.1 Der Agent arbeitet

`m2-agent` schickt dieselben Hook-Ereignisse wie Claude Code an `minds hook`
und schreibt dazwischen die Dateien; am Mac stattdessen `claude` mit einem
Prompt, der nur `src/a.rs` und `src/b.rs` ändert und nicht committet.

```sh
sudo -iu agent sh -c 'cd ~/demo && m2-agent s1 "Implementiere a und b" "src/a.rs=fn a() -> u8 { 1 }" "src/b.rs=fn b() -> u8 { 2 }"'
```

### 2.2 Checkpoint (Commit) und Vorschau

```sh
sudo -iu agent sh -c 'cd ~/demo && git add src && git commit -qm "feat: a und b" && minds bind --dry-run HEAD'
```

```text
minds: e002ac51f406 would bind 1 seal(s): 2/2 files covered (dry run, nothing signed)
```

Der Commit trägt `Minds-Session-Id`; unter `refs/minds/evidence/` und
`refs/minds/observations/` liegen Seals und Observations des Witness.

### 2.3 Pre-Push: Binden, Evidence, Code, Quittung

```sh
sudo -iu agent sh -c 'cd ~/demo && git push origin main'
```

```text
minds: 1 commit(s) bound, 0 already bound, 0 without evidence
minds: evidence transferred (3 refs)
minds: 5 ref(s) → origin in the background
   df4cc3d..e002ac5  main -> main
```

Am Server danach: `refs/minds/bindings/<c>/…`, `refs/minds/witness/keys`,
`…/witness/trust/<hex>`, `…/witness/receipts/<c>/<hex>`.

### 2.4 Vertrauensanker des Prüfers (Server-Betreiber, root)

```sh
KEY=$(sudo -u minds-git git -C /home/minds-git/demo.git cat-file blob refs/minds/witness/keys:keys.json \
      | sed -n 's/.*"key":"\(ed25519:[0-9a-f]*\)".*/\1/p')
install -d -m 0755 -o root -g root /etc/minds
printf '%s\n' "$KEY" > /root/receipt-keys && install -m 0644 -o root -g root /root/receipt-keys /etc/minds/receipt-keys
```

### 2.5 Unabhängiges Verify aus einem frischen Clone (als `pruefer`)

```sh
sudo -iu pruefer sh -c '
git clone -q -u "sudo -n -u minds-git /usr/bin/git-upload-pack" file:///home/minds-git/demo.git demo && cd demo
git config remote.origin.uploadpack "sudo -n -u minds-git /usr/bin/git-upload-pack"
git for-each-ref refs/minds/ | wc -l          # 0 — keine minds-Refs, kein minds enable
minds verify --receipt --remote origin --project git.example.test/project-42 --require-protected-anchor; echo EXIT=$?'
```

```text

  Vertrauensanker: geschützt (/etc/minds/receipt-keys)
  Projekt: git.example.test/project-42 (bestätigt durch --project)
  Signatur: gültig (Schlüssel ed25519:e26860ba…, gültig seit 2026-10-01T00:00:00Z)
  Vertrauenskontext: blake3:6eaa9623… vorhanden, Hash stimmt mit der signierten Quittung (require_separated_witness = true)
  Evidence: vom Remote origin beschafft (1 Bindung, 1 Seal, 1 Observations)

  Zustand: Verified, 2/2 Dateien nachgewiesen (100,0 %), Policy erfüllt (observe, Schwelle 100 %)
```

Für jeden weiteren Push prüft der Prüfer den neuen Stand mit

## Teil 3 · Szenario 2: Handänderung und `Partial`

### 3.1 (2a) Handänderung im Worktree — der Witness sieht sie

```sh
sudo -iu agent sh -c 'cd ~/demo && m2-agent s2 "Ändere a und b" "src/a.rs=fn a() -> u8 { 10 }" "src/b.rs=fn b() -> u8 { 20 }" \
  && printf "fn c() -> u8 { 30 }\n" > src/c.rs && git add src && git commit -qm "feat: a, b (Agent) und c (von Hand)" && git push -q origin main'
```

verify: `Zustand: Verified, 3/3 Dateien nachgewiesen (100,0 %)`, Exit 0.

### 3.2 (2b) Inhalt am Witness vorbei — `Partial, 2/3`

```sh
sudo -iu agent bash -c 'cd ~/demo && m2-agent s3 "Ändere a und b erneut" "src/a.rs=fn a() -> u8 { 100 }" "src/b.rs=fn b() -> u8 { 200 }"
blob=$(printf "fn c() -> u8 { 300 }\n" | git hash-object -w --stdin)
git update-index --cacheinfo 100644,$blob,src/c.rs
git add src/a.rs src/b.rs && git commit -qm "feat: a, b (Agent), c am Witness vorbei" && git push origin main'
```

```text
remote: minds-witness: Warnung: refs/heads/main a6b7efe3456b: Partial, 2/3 Dateien nachgewiesen (66,7 %), Evidence-Policy nicht erfüllt (Schwelle 100 %)
remote: minds-witness: Push wird von minds nicht blockiert. Nachweis unvollständig; Details in der Quittung.
```

verify: `Zustand: Partial, 2/3 Dateien nachgewiesen (66,7 %), Policy nicht erfüllt (observe, Schwelle 100 %)`, **Exit 2**.

## Teil 4 · Szenario 3: Strict Enforce

Server-Betreiber: Policy auf Enforce für `main` (neue Version):

```sh
sudo -iu minds-git sed -i 's/"mode": "observe"/"mode": "enforce"/; s/"enforce_refs": \[\]/"enforce_refs": ["refs\/heads\/main"]/; s/"version": 1/"version": 2/' witness/hook.json
```

Derselbe Fall wie 2b:

```sh
sudo -iu agent bash -c 'cd ~/demo && m2-agent s4 "Enforce-Probe" "src/a.rs=fn a() -> u8 { 1000 }" "src/b.rs=fn b() -> u8 { 2000 }"
blob=$(printf "fn c() -> u8 { 3000 }\n" | git hash-object -w --stdin); git update-index --cacheinfo 100644,$blob,src/c.rs
git add src/a.rs src/b.rs && git commit -qm "feat: Enforce-Probe" && git push origin main; echo PUSH_EXIT=$?'
```

```text
remote: minds-witness: Push auf refs/heads/main abgelehnt: Commit dfac6a03… (2/3 Pfade abgedeckt, Seal valid)
 ! [remote rejected] main -> main (pre-receive hook declined)
PUSH_EXIT=1
```

`main` am Server unverändert, keine neue Quittung. Nachgeholt (`c` beobachtet
geschrieben, Amend):

```sh
sudo -iu agent sh -c 'cd ~/demo && m2-agent s4 "Auch c" "src/c.rs=fn c() -> u8 { 3000 }" && git add src/c.rs && git commit -q --amend --no-edit && git push origin main'
```

Angenommen; verify: `Zustand: Verified, 3/3 Dateien nachgewiesen (100,0 %), Policy erfüllt (enforce, Schwelle 100 %)`, Exit 0.

## Mac (nicht in diesem Lauf ausgeführt)

Gleiche Schritte mit drei Unterschieden: der Witness heißt `_minds` und läuft
als LaunchDaemon (kein Ersatz für systemctl); `minds-git` und `pruefer` legt
`sudo sysadminctl -addUser <name>` an; `acl` braucht es nicht. Der Agent ist
`claude` statt `m2-agent`.

## Befunde aus dem Lauf

1. **Handänderungen zählen als beobachtet.** Der Witness bezeugt Inhalt im
   Worktree, nicht, wer ihn schrieb (Szenario 2a). `Partial` braucht Inhalt,
   den er nie sah. Produktfrage, keine Abweichung im Code.
2. **`minds enable --project` bei laufendem Witness** meldet „does not answer“
   und versucht die geschützte Einrichtung erneut (scheitert ohne `sudo`, fällt
   auf den ungeschützten zurück, der ohne User-systemd ebenfalls scheitert).
   Der Witness läuft dabei unverändert weiter. Umgehung: nach der Einrichtung
   `enable` ohne `--project`.
3. **`git config minds.project` setzt `enable` nicht**, obwohl `--project`
   übergeben wurde; ohne ihn bindet der pre-push-Hook nichts.
