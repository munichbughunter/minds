1//! Der gemeinsame Umschlag eines Agent-Hook-Payloads — und seine Übersetzung
2//! in ein [`NewEvent`].
3//!
4//! Dieses Modul ist die Grenze zwischen fremdem Format und unserem. Alles, was
5//! wüsste, wie *ein bestimmter Agent* seine Events benennt, gehört hierher und
6//! nicht in die CLI. In M5.4 wächst genau das hier zum Normalisierer heran:
7//! heute ein gemeinsamer Umschlag für alle, morgen ein `match` je Agent für
8//! das, was sich unterscheidet.
9//!
10//! # Eine reine Funktion, mit Absicht
11//!
12//! [`parse`] liest keine Uhr, kein Verzeichnis und keine Umgebungsvariable. Der
13//! Zeitpunkt wird **hereingereicht**. Das kostet den Aufrufer eine Zeile und
14//! kauft dafür Fixture-Tests: Dieselben Bytes ergeben immer dasselbe Event,
15//! Byte für Byte. Wäre die Uhr hier drin, wäre jeder Testlauf ein anderer und
16//! der Vertrag „gleicher Journal-Inhalt ⇒ gleiche `SessionId`" nicht prüfbar.
17//!
18//! Wer *wo* ist (Arbeitsverzeichnis, Repository) bleibt deshalb ebenfalls beim
19//! Aufrufer. Dieses Modul sagt nur, was der Payload behauptet — siehe
20//! [`ParsedEvent::cwd`].
21//!
22//! # Ein kaputter Payload kostet nicht das Event
23//!
24//! Der Payload kann unvollständig ankommen — der Regelfall ist Abschneiden an
25//! der stdin-Grenze der CLI. Das trifft ausgerechnet die Events, die man am
26//! wenigsten verlieren will: `PostToolUse` mit großer Tool-Ausgabe, also
27//! genau die Datei-Lesungen und Kommandoausgaben, die den Record wertvoll
28//! machen.
29//!
30//! Deshalb zwei Rettungsstufen, bevor irgendetwas verworfen wird:
31//!
32//! 1. Scheitert der JSON-Parser, wird der Umschlag per [`salvage`] aus den
33//! Rohbytes gefischt. Die gesuchten Felder stehen bei allen bekannten
34//! Agents weit vorn — vor dem Feld, das den Payload groß macht.
35//! 2. Der Payload selbst wird als JSON-**Zeichenkette** abgelegt statt
36//! weggeworfen. Beweismittel werden nicht entsorgt, nur weil sie beschädigt
37//! sind; der Adapter sieht am Typ sofort, dass hier etwas nicht stimmte.
38//!
39//! Was dabei **nicht** aufgeweicht wird, ist die Prüfung des
40//! [`SessionKey`]: Geratenes darf ins Journal, aber nicht in einen Pfad.
41

50/// Ergebnis von [`parse`]: das fertige Event plus die Angaben, die der
51/// Aufrufer für die Ablage braucht.
52#[derive(Debug)]
53pub struct ParsedEvent {
54 /// Wohin das Event gehört.
55 pub key: SessionKey,
56
57 /// Das Event selbst, ohne Sequenznummer — die vergibt das Journal.
58 pub event: NewEvent,
59
60 /// Das Arbeitsverzeichnis laut Payload, falls genannt.
61 ///
62 /// Der Aufrufer sollte es der eigenen `current_dir` **vorziehen**: Agents
63 /// starten Hooks nicht zwingend im Projektverzeichnis, und ein Hook, der
64 /// das falsche Repository findet, schreibt ins falsche Journal.
65 pub cwd: Option<PathBuf>,
66}
67
68/// Übersetzt einen rohen Hook-Payload in ein Journal-Event.
69///
70/// `agent` kommt aus der Hook-Registrierung, nicht aus dem Payload: Wer uns
71/// aufruft, weiß besser, wer er ist, als das JSON, das er schickt.
72///
73/// `event_override` füllt die Lücke bei Agents, die den Eventnamen nicht
74/// mitschicken, sondern nur über die Registrierung kennen.
75///
76/// `at` ist die Ablesung des Aufrufers, üblicherweise [`crate::clock::now`].
77pub fn parse(
78 bytes: Vec<u8>,
79 agent: &str,
80 event_override: Option<&str>,
81 at: (String, u64),
82) -> Result<ParsedEvent> {
83 let envelope: Envelope = serde_json::from_slice(&bytes).unwrap_or_else(|_| salvage(&bytes));
84
85 let local_id = envelope
86 .session_id
87 .clone()
88 .or_else(|| transcript_stem(envelope.transcript_path.as_deref()))
89 .ok_or(CaptureError::NoSessionKey)?;
90
91 // Die Pruefung sitzt hier und nirgends sonst: Was `salvage` geraten hat,
92 // muss dieselbe Huerde nehmen wie sauber geparste Werte.
93 let key = SessionKey::new(agent, local_id)?;
94
95 let raw_kind = envelope
96 .hook_event_name
97 .clone()
98 .or_else(|| event_override.map(str::to_owned))
99 .unwrap_or_else(|| "Unknown".to_string());
100
101 let (at_text, at_nanos) = at;
102
103 Ok(ParsedEvent {
104 cwd: envelope.cwd.as_deref().map(PathBuf::from),
105 key,
106 event: NewEvent {
107 at: at_text,
108 at_nanos,
109 kind: classify(&raw_kind),
110 raw_kind,
111 cwd: envelope.cwd,
112 transcript_path: envelope.transcript_path,
113 payload: payload_of(bytes),
114 },
115 })
116}

118/// Der gemeinsame Umschlag, den alle unterstützten Agents schicken.
119///
120/// Jedes Feld ist optional, und ein unbekanntes Feld ist kein Fehler: Der
121/// Payload gehört jemand anderem und darf sich ändern, ohne dass der Rekorder
122/// bricht. Was wir nicht verstehen, liegt trotzdem vollständig im Journal.
123#[derive(Debug, Default, Deserialize)]
124#[serde(default)]
125struct Envelope {
126 session_id: Option<String>,
127 transcript_path: Option<String>,
128 cwd: Option<String>,
129 hook_event_name: Option<String>,
130}
131
132/// Rettet den Umschlag aus JSON, das sich nicht parsen lässt.
133///
134/// Bewusst dumm: kein Parser, keine Escape-Behandlung, erstes Vorkommen
135/// gewinnt. Ein Wert mit `\"` darin liefert hier Unsinn — und dieser Unsinn
136/// wird anschließend von [`SessionKey::new`] abgelehnt, wo die eigentliche
137/// Prüfung sitzt. Diese Funktion darf raten; sie darf nur nichts durchlassen,
138/// was gefährlich ist.
139fn salvage(bytes: &[u8]) -> Envelope {
140 let text = String::from_utf8_lossy(bytes);
141 Envelope {
142 session_id: scan(&text, "session_id"),
143 transcript_path: scan(&text, "transcript_path"),
144 cwd: scan(&text, "cwd"),
145 hook_event_name: scan(&text, "hook_event_name"),
146 }
147}
148
149/// Sucht `"key": "wert"` und gibt den Wert zurück.
150fn scan(text: &str, key: &str) -> Option<String> {
151 let needle = format!("\"{key}\"");
152 let rest = &text[text.find(&needle)? + needle.len()..];
153 let rest = rest.trim_start().strip_prefix(':')?.trim_start();
154 let rest = rest.strip_prefix('"')?;
155 let end = rest.find('"')?;
156 Some(rest[..end].to_string())
157}

159/// Bildet den Eventnamen des Agenten auf unser Vokabular ab.
160///
161/// Unbekanntes wird zu [`EventKind::Other`] und **nicht** zum Fehler — das
162/// Vokabular der Agents wächst schneller als unseres, und der Originalname
163/// bleibt über `raw_kind` ohnehin erhalten.
164///
165/// `PostToolUseFailure` fällt bewusst mit `PostToolUse` zusammen: Ein
166/// fehlgeschlagener Tool-Call ist für den Record dasselbe Ereignis wie ein
167/// gelungener — was ihn unterscheidet, steht im Payload und geht nicht
168/// verloren.
169fn classify(raw: &str) -> EventKind {
170 match raw {
171 "SessionStart" => EventKind::SessionStart,
172 "SessionEnd" => EventKind::SessionEnd,
173 "UserPromptSubmit" => EventKind::Prompt,
174 "PreToolUse" => EventKind::ToolPre,
175 "PostToolUse" | "PostToolUseFailure" => EventKind::ToolPost,
176 "Stop" | "StopFailure" => EventKind::TurnEnd,
177 "SubagentStart" => EventKind::SubagentStart,
178 "SubagentStop" => EventKind::SubagentEnd,
179 _ => EventKind::Other,
180 }
181}
182
183/// Notnagel, wenn der Payload keine Session-Kennung nennt: Claude Code
184/// benennt die Transkriptdatei nach der Session.
185fn transcript_stem(path: Option<&str>) -> Option<String> {
186 Path::new(path?)
187 .file_stem()
188 .and_then(|s| s.to_str())
189 .map(str::to_owned)
190}
191
192/// Verpackt die Rohbytes als JSON-Wert.
193///
194/// Ist der Payload gültiges JSON, wandert er **unverändert** ins Journal —
195/// keine umsortierten Schlüssel, keine umgeschriebenen Zahlen. Ist er es nicht,
196/// wird er als JSON-Zeichenkette abgelegt statt verworfen.
197fn payload_of(bytes: Vec<u8>) -> Box<RawValue> {
198 let text = String::from_utf8_lossy(&bytes).into_owned();
199
200 if let Ok(raw) = RawValue::from_string(text.clone()) {
201 return raw;
202 }
203
204 // `to_string` einer Zeichenkette kann nicht fehlschlagen, und das Ergebnis
205 // ist per Konstruktion gueltiges JSON.
206 RawValue::from_string(serde_json::to_string(&text).unwrap_or_else(|_| "\"\"".into()))
207 .unwrap_or_else(|_| RawValue::from_string("null".into()).expect("null ist JSON"))
208}

Absicht

Ich möchte M5 so umbauen, dass wir es genauso machen wie entire! Mit dem Hook-Ansatz. Wir bleiben erst einmal bei der Rust implementierung. Diese ist effizienter. Das ist der entscheidende Unterschied. Bei Codex wird zusätzlich `codex_hooks = true` in die `config.toml` geschrieben. Dazu Git-Hooks: Checkpoints entstehen, wenn du oder der Agent committen; die Session-Metadaten möchte ich entweder auf einem child-repo haben oder falls wir diese kombination nicht haben direkt im repo. Das Verhalten soll an der Stelle absolut gleich sein.
